# v0.9.270-v0.9.274 Matrix/Memory/MFG/WebUI Evolution Plan

## Status

Superseded and archived.

Do not execute this plan. It kept compatibility aliases, legacy API routes and migration facades that conflict with the current full Matrix/MFG/WebUI refactor target. The active source of truth is `docs/plans/v0.9.275-v0.9.282-matrix-mfg-webui-full-refactor.md`.

## Direction

`iacc` is re-scoped as the structured fact engine in the Cowd kernel and is renamed `matrix`.
`memory` remains the unstructured fact engine. Together they form the two fact engines that feed
context, agents, skills, tools, and cross-plane actions.

Manufacturing is not the kernel. It becomes the first upper application, named `mfg`, built on top
of Matrix, Memory, runtime, skills, and cross-plane dispatch.

WebUI is not a compile-time Rust dependency. It becomes a shell that loads pages/plugins by
manifest. MFG pages are application plugins, not hard-coded kernel UI.

## Final Target

```text
kernel
  runtime
  memory                 # unstructured fact engine
  matrix                 # structured fact engine, formerly iacc core
  context                # memory + matrix evidence fusion
  skills/tools/agents
  cross-plane/governance

apps
  mfg                    # manufacturing domain, ontology, skills, cockpit, API adapter

surfaces
  tui                    # runtime management surface
  webui-shell            # pluggable browser shell
  mfg-webui-plugin       # manufacturing pages loaded by manifest
```

Dependency rule:

```text
runtime/kernel -> matrix + memory primitives only
mfg -> matrix + memory + runtime
webui-shell -> manifest + generated/open API client
mfg-webui-plugin -> mfg app API contract
matrix must never depend on mfg or webui
memory must never depend on mfg or webui
```

## v0.9.270 - Matrix Kernel Identity and Compatibility

Goal:
Introduce Matrix as the canonical structured fact engine while keeping existing IACC callers stable.

Deliverables:
- Add `runtime::matrix` as the kernel-facing module.
- Keep `runtime::iacc` as a compatibility facade.
- Add `Matrix*` aliases for core `Iacc*` types where immediate rename is low risk.
- Add `matrix_reference(kind, id)` using `matrix:` references.
- Add capability declaration `cowd.matrix.runtime`.
- Keep `iacc.manufacturing.application` temporarily, but mark it as an application capability over Matrix.
- Add tests proving Matrix and IACC compatibility point to the same store/model behavior.

TDD:
- `matrix_reference_uses_matrix_namespace`
- `matrix_store_alias_opens_and_uses_iacc_store_compatibly`
- `capability_registry_declares_matrix_as_kernel_fact_engine`
- `iacc_reference_remains_available_for_compatibility`

Acceptance:
- `cargo check -p runtime`
- `cargo test -p runtime matrix`
- Existing IACC API tests continue to compile unchanged.

Audit focus:
- No manufacturing code is introduced into `matrix` during this version.
- No endpoint is removed.
- Public compatibility aliases are explicit and documented.

## v0.9.271 - Matrix API Boundary and IACC Route Compatibility

Goal:
Split API naming from implementation without breaking clients.

Deliverables:
- Add `/api/matrix/*` routes for structured fact engine primitives:
  - `/api/matrix/health`
  - `/api/matrix/entities`
  - `/api/matrix/facts/ingest`
  - `/api/matrix/relations/upsert`
  - `/api/matrix/metrics`
  - `/api/matrix/evidence/build`
  - `/api/matrix/compute/jobs/*`
- Keep `/api/iacc/*` as compatibility aliases.
- Rename internal route helpers from `iacc_*` to `matrix_*` where they are kernel-generic.
- Keep manufacturing-specific routes out of Matrix:
  - `/api/apps/mfg/*` will be introduced in v0.9.272.

TDD:
- Matrix and IACC compatibility endpoints return equivalent payloads for core structured operations.
- Write operations preserve idempotency/session/outcome records through both route families.
- Route naming audit fails if generic Matrix endpoints contain `server_manufacturing`.

Acceptance:
- `cargo test -p cowd-cli matrix`
- `cargo test -p cowd-cli iacc`
- WebUI IACC compatibility tests remain green.

Audit focus:
- API compatibility is additive.
- No generic Matrix route calls manufacturing seed/domain/skill functions.

## v0.9.272 - MFG Application Extraction

Goal:
Move manufacturing domain/application assets out of Matrix kernel into `mfg`.

Deliverables:
- Create `crates/mfg-app` or `apps/mfg`.
- Move these into MFG:
  - `server_manufacturing_domain_pack`
  - `server_manufacturing_seed_plan`
  - `server_manufacturing_ontology_pack`
  - `server_manufacturing_skill_pack`
  - manufacturing skill plan/run functions
  - manufacturing app descriptor
- Add `MfgApplicationModule` with capability manifest and router registration.
- Add `/api/apps/mfg/*` routes:
  - `/api/apps/mfg/app`
  - `/api/apps/mfg/domain/server-manufacturing/seed`
  - `/api/apps/mfg/ontology/server-manufacturing/seed`
  - `/api/apps/mfg/skills`
  - `/api/apps/mfg/incidents/*`
- Keep `/api/iacc/domain/server-manufacturing/*` compatibility shims until migration completes.

TDD:
- Matrix crate has no `server_manufacturing` symbols.
- MFG app tests cover domain seed, ontology seed, skill plan/run, incident room.
- Compatibility routes call MFG module, not Matrix internals.

Acceptance:
- `cargo check -p runtime`
- `cargo check -p mfg-app`
- `cargo test -p mfg-app`
- `cargo test -p cowd-cli mfg`

Audit focus:
- One-way dependency: MFG depends on Matrix; Matrix does not depend on MFG.
- Domain packs are application data, not kernel data.

## v0.9.273 - Pluggable WebUI Shell and MFG Page Plugin

Goal:
Make WebUI pages application plugins and remove Rust default coupling to WebUI builds.

Deliverables:
- Split WebUI shell from application pages:
  - `webui/shell`
  - `webui/plugins/mfg`
- Add plugin manifest:
  - route id
  - nav label/icon
  - required capabilities
  - API namespace
  - lazy component entrypoint
- Move MFG page code out of generic capability pages.
- Keep legacy `/iacc` route as redirect/alias to `/apps/mfg` during migration.
- Update WebUI tests to load plugin manifest.
- Gate `cowd-cli/build.rs` WebUI asset copy behind `embedded-webui`.

TDD:
- Shell boots without MFG plugin.
- MFG plugin registers nav and route when manifest is present.
- Rust `cargo check -p cowd-cli` does not require WebUI files unless `embedded-webui` is enabled.
- WebUI plugin tests cover MFG page behavior independently.

Acceptance:
- `cargo check -p cowd-cli`
- `cargo check -p cowd-cli --features embedded-webui`
- `npm test --prefix webui/shell`
- `npm test --prefix webui/plugins/mfg`

Audit focus:
- WebUI build artifacts are not copied during default Rust builds.
- No MFG literals in shell except compatibility route mapping.

Audit focus:

## Cross-Version Audit Checklist

- Naming:
  - `matrix` means structured fact engine.
  - `memory` means unstructured fact engine.
  - `mfg` means manufacturing application.
  - `iacc` is only compatibility naming after v0.9.271.
- Dependency:
  - Kernel does not depend on application crates.
  - Application crates depend on kernel contracts.
  - WebUI shell depends on manifests/contracts, not app internals.
- Build:
  - Default Rust build does not build or copy WebUI.
  - App-specific crates compile only when selected.
  - WebUI plugins test independently.
- Runtime:
  - Existing data remains readable.
  - Old IACC stores migrate or alias to Matrix stores.
  - Compatibility endpoints remain until explicitly removed.
- Safety:
  - Every version lands behind tests.
  - No route deletion without compatibility alias.
  - No type rename without alias during migration.

## Implementation Mode

Each version follows:

1. Add failing boundary/contract tests.
2. Implement the minimal code to pass.
3. Run focused tests.
4. Run compile checks for affected crates.
5. Update this plan with any deviation.
6. Submit audit notes before moving to the next version.
