# v0.9.79 IACC 证据、上下文与数字员工链路

## 版本定位

`v0.9.79` 在 IACC 数据接入、指标重算与注意力事件之上，打通第一条“运营问题进入现有 AI 基座”的闭环通道。

本版本不新建孤立的问题处理系统，而是把 IACC 的结构化证据包投影为 Context Runtime 可消费的 `ContextItem`，并通过 incident API 创建现有 `TaskKernel` 任务和 `AgentRunGraph`，让 IACC 复用已有任务、多智能体协作、运行事件和上下文能力。

## 核心能力

- EvidencePacket 汇聚 attention 关联的 change event 与 metric state。
- EvidencePacket 可转换为统一上下文项 `ContextItem`。
- 新增 `IaccIncident`，作为运营问题处置入口。
- Incident 创建时自动创建任务，并补齐 IACC 专用数字员工节点：
  - `iacc_researcher`：核验证据和缺口。
  - `iacc_reviewer`：审查置信度、冲突和治理可用性。
  - `iacc_merger`：合并结论为可治理运营决策。
- IACC Workgraph 事件写入前会确保 task session 记录存在，兼容统一事件表外键约束。

## API

- `GET /api/iacc/evidence/:id/context`
- `POST /api/iacc/incidents`
- `GET /api/iacc/incidents/:id`

`GET /api/iacc/health` 新增：

- `incident_count`
- capability: `evidence_context_item`
- capability: `incident_agent_graph`

## 数据库

IACC schema version 升级到 `3`。

新增表：

- `iacc_incident`

核心字段：

- `incident_id`
- `title`
- `attention_id`
- `evidence_packet_id`
- `task_id`
- `agent_graph_id`
- `status`
- `created_at`
- `updated_at`

## 与 v0.9.78 的区别

`v0.9.78` 解决结构化事实如何形成指标状态、变化事件和注意力。

`v0.9.79` 解决已发现的运营问题如何进入现有 AI 大脑，成为可分析、可审查、可协作处理的任务。
