# v0.9.81 IACC 处置动作执行回执与反馈闭环

## 版本定位

`v0.9.81` 在 `v0.9.80` 的归因、影响路径和推荐处置建议之上，补齐从推荐动作到治理执行回执，再到人工反馈和 incident 关闭的闭环。

本版本仍保持 IACC 的运营层边界：它不直接替代 ERP、MES、PLM、SRM 等源系统执行真实写操作，而是生成可审计的 action execution receipt。真实企业系统调用可在后续通过 connector/cross-plane adapter 接入。

## 核心能力

- 新增 `IaccActionExecutionRequest`。
- 新增 `IaccActionExecution`。
- 新增 `IaccActionFeedback`。
- 支持对 analysis 中的 recommended action 发起执行：
  - `dry_run`
  - `commit`
- `commit` 当前进入 `queued_for_human_review`，符合 `human_review_required` 治理边界。
- execution 持久化 receipt。
- 支持 feedback 回写：
  - `resolved`
  - `accepted`
  - `executed`
  - `rejected`
  - `needs_followup`
- `resolved/accepted/executed` 会把 incident 状态更新为 `closed`。

## API

- `POST /api/iacc/analyses/:analysis_id/actions/:action_id/execute`
- `GET /api/iacc/executions/:id`
- `POST /api/iacc/executions/:id/feedback`

`GET /api/iacc/health` 新增：

- `execution_count`
- capability: `action_execution_feedback`

- `incident_id`

- `updated_at`

## 闭环语义

1. EvidencePacket 形成结构化证据。
2. Incident 创建任务和 AgentRunGraph。
3. Incident analyze 生成归因、影响路径和 recommended action。
4. Recommended action execute 生成治理回执。
5. 人类或外部系统 feedback 回写结果。
6. resolved/accepted/executed 将 incident 关闭。

这完成了 IACC 第一套从感知、分析、建议到反馈闭环的最小可运行骨架。

## 验收

新增脚本：

- `scripts/v0981_iacc_action_feedback_scenario.sh`

脚本验证：

- gateway 启动。
- IACC schema version 为 5。
- fact ingest、metric recompute、attention、evidence、incident、analysis 均正常。
- recommended action 可执行。
- execution receipt 为 `iacc.action.execution`。
- commit 执行进入 `queued_for_human_review`。
- feedback resolved 后 execution 状态为 `feedback_resolved`。
- incident 状态变为 `closed`。
- health 中 `execution_count` 为 1。

## 与 v0.9.80 的区别

`v0.9.80` 生成可审查处置建议。

`v0.9.81` 让处置建议进入治理执行与反馈闭环，形成 IACC 第一套完整运营闭环骨架。
