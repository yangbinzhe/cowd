# v0.9.95 IACC Cockpit Report Schedule Runner

## Goal

`v0.9.95` adds the first operational report schedule runner. The runner scans
cockpit profiles by cadence, generates report snapshots, and can immediately
deliver those reports through the same payload rendering and cross-plane
governance bridge introduced in `v0.9.93` and `v0.9.94`.

## Scope

- Add `IaccStore::list_cockpit_profiles`.
- Add `POST /api/iacc/cockpit/reports/schedules/run`.
- Filter profiles by cadence.
- Generate one report snapshot per matched profile.
- Support deterministic `report_id_prefix` for repeatable scheduled runs.
- Optionally deliver generated reports through cross-plane.
- Reuse the same delivery payload templates, audit ledger, execution receipt,
  and idempotency logic as manual report delivery.
- Keep schema version at `11`.

## API Contract

Request:

```json
{
  "request_id": "v0995",
  "cadence": "daily",
  "limit": 10,
  "report_id_prefix": "cockpit-report-v0995",
  "delivery_ref": "channel://feishu/user/ops-planner",
  "deliver": true,
  "mode": "dry_run",
  "channel": "feishu",
  "template_id": "ops.alert.compact",
  "actor_principal": "user:ops-planner",
  "actor_identity_ref": "iacc://operator/ops-planner"
}
```

Response:

```json
{
  "kind": "iacc.cockpit.report_schedule_run",
  "matched_profile_count": 1,
  "generated_report_count": 1,
  "delivery_count": 1,
  "items": [
    {
      "profile_id": "cockpit-profile-v0995-ops",
      "report": {},
      "delivery": {}
    }
  ]
}
```

Each delivery item contains the same `IaccCockpitReportDeliveryOutcome` returned
by manual report delivery.

## Idempotency

Scheduled delivery idempotency key:

```text
iacc-schedule:{request_id}:{report_id}:{delivery_index}
```

If the same schedule run is repeated with the same request id and deterministic
report id prefix, the report snapshot is regenerated, then the existing
cross-plane receipt is replayed and re-attached to the report snapshot without
duplicating delivery receipts.

## Acceptance

`scripts/v0995_iacc_cockpit_report_schedule_runner_scenario.sh` validates:

- health advertises `cockpit_report_schedule_runner`;
- cadence filter selects the expected cockpit profile;
- schedule runner generates one report;
- optional delivery creates a cross-plane receipt;
- delivery payload template data is present;
- schedule replay is idempotent and does not duplicate delivery receipts.

## Next Version

`v0.9.96` should add typed delivery retry/error classification so blocked,
failed, and replayed deliveries can be inspected and re-run deliberately from
