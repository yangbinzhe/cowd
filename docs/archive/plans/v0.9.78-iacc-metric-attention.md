# v0.9.78 IACC Metric/Attention

## 目标

在 `v0.9.77 IACC Foundation` 之上，打通第一条结构化运营认知链路：

```text
Fact -> MetricState -> ChangeEvent -> Attention
```

本版本聚焦指标网络底座的最小可运行闭环，先不进入完整 BOM 依赖图、复杂归因和影响传播。

## 实施内容

- 工作区版本号从 `0.9.77` 提升到 `0.9.78`。
- 新增 IACC metric/change 契约：
  - `IaccMetricDefinition`
  - `IaccMetricState`
  - `IaccMetricStatus`
  - `IaccChangeEvent`
  - `IaccMetricRecomputeResult`
- IACC SQLite schema 升级到 version 2。
- 新增表：
  - `iacc_metric_definition`
  - `iacc_metric_state`
  - `iacc_change_event`
- 新增指标重算能力：
  - 按 `metric_key + entity + period` 聚合事实。
  - 从 fact measures 中提取数值并求和。
  - 生成 materialized metric state。
  - 与上一状态比较生成 change event。
  - 基于 change event 生成 metric-driven attention。
- 新增 API：
  - `GET /api/iacc/metrics`
  - `GET /api/iacc/metrics/:id`
  - `POST /api/iacc/metrics/recompute`
  - `GET /api/iacc/changes`
- 新增真实 gateway 场景脚本：
  - `scripts/v0978_iacc_metric_attention_scenario.sh`

## 架构边界

本版本仍保持低冲突接入：

- 不修改 connector/resource directory schema。
- 不修改 memory runtime schema。
- 不修改 cross-plane policy 语义。
- 不修改 daemon socket protocol。
- 不改 WebUI 面板结构。

## 处理策略

本版本的 metric recompute 是后续大规模处理的最小骨架：

```text
事实入库
-> 选择带 metric_key 的事实
-> 按 metric/entity/period 分组
-> 聚合数值 measures
-> 写入 metric_state
-> 对比上一 metric_state
-> 写入 change_event
-> 写入 attention
```

这为后续版本继续扩展以下能力留出边界：

- 指标依赖图。
- 局部重算。
- BOM/计划差异传播。
- 异常检测。
- 归因和影响路径。
