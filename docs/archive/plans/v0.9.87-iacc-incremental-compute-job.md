# v0.9.87 IACC Incremental Compute Job

## Goal

Add the first incremental compute job layer. IACC can now map a changed fact type
to affected metrics through the metric dependency graph, persist a compute job,
and run a scoped metric recompute for only the affected metrics.

This version does not yet introduce a distributed compute engine. It creates the
runtime contract and execution boundary required before scale benchmarking and
external engines are introduced.

## Runtime Contracts

New contracts:

- `IaccComputeJobInput`
- `IaccComputeJob`
- `IaccComputePlan`

## Store

Schema version is now `8`.

New table:

- `iacc_compute_job`

New store capabilities:

- `plan_compute_job_for_fact_type`
- `get_compute_job`
- `run_compute_job`
- `recompute_metrics_for_metric_ids`

`run_compute_job` currently performs a scoped local recompute. It filters metric
facts by the job's affected metric ids, so a supplier commitment change does not
recompute unrelated work-center or quality metrics.

## API

New routes:

- `POST /api/iacc/compute/jobs/plan`
- `GET /api/iacc/compute/jobs/:id`
- `POST /api/iacc/compute/jobs/:id/run`

`GET /api/iacc/health` now returns:

- `compute_job_count`

New health capabilities:

- `incremental_compute_job`
- `scoped_metric_recompute`

## Acceptance

Runtime tests prove:

- `supply.commit_variance` plans a compute job for supplier, material shortage,
  and delivery risk metrics;
- running that job recomputes only three affected metrics;
- unrelated work-center load states are not recomputed by the supply job.

Scenario script:

```text
scripts/v0987_iacc_incremental_compute_job_scenario.sh
```

The scenario proves through gateway API:

1. schema version 8 is exposed;
2. incremental compute capabilities are visible;
3. server manufacturing seed creates dependencies and facts;
4. fact-type planning returns affected metrics;
5. running the job completes it and records result summary;
6. health reports persisted compute jobs;
7. previous v0.9.86/v0.9.85/v0.9.81 scenarios remain compatible.
