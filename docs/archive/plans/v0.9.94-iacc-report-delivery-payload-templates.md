# v0.9.94 IACC Report Delivery Payload Templates

## Goal

`v0.9.94` turns cockpit report delivery from an ad hoc text fallback into a
stable payload rendering contract. The IACC report layer now produces a typed
delivery payload before cross-plane policy execution, so future live adapters
can consume a predictable payload shape without knowing cockpit internals.

## Scope

- Add `IaccCockpitReportDeliveryPayload`.
- Add `IaccCockpitReportDeliveryPayloadRequest`.
- Infer delivery channel from explicit request, capability, or target ref.
- Render compact Feishu, email, and webhook-oriented payload templates.
- Keep `resource_ref` as `text://...` so the current cross-plane dispatch
  contract remains usable.
- Add delivery payload data to the report delivery API response.
- Advertise `cockpit_report_payload_templates` in IACC health.
- Keep schema version at `11`.

## Runtime Contract

Delivery request can now include:

```json
{
  "mode": "dry_run",
  "channel": "feishu",
  "template_id": "ops.alert.compact",
  "target_ref": "channel://feishu/user/ops-planner"
}
```

Response includes:

```json
{
  "delivery_payload": {
    "channel": "feishu",
    "template_id": "ops.alert.compact",
    "requested_capability": "channel.feishu.send_text",
    "resource_ref": "text://...",
    "constraints": [
      "payload_kind:text",
      "cross_plane_policy_required",
      "report_snapshot_required",
      "channel:feishu",
      "capability:channel.feishu.send_text",
      "target_ref_present"
    ]
  }
}
```

The cross-plane action uses the rendered payload as its default `resource_ref`.
If callers explicitly provide `resource_ref`, the explicit value still wins,
but the response continues to expose the rendered payload for audit and preview.

## Design Decisions

- The version does not introduce a separate notification service.
- The payload remains text-compatible because current live dispatch supports
  text, image, and file payload kinds.
- Channel-specific templates are a runtime contract, not UI-only formatting.
- Policy and idempotency remain owned by cross-plane.

## Acceptance

`scripts/v0994_iacc_report_delivery_payload_templates_scenario.sh` validates:

- health advertises `cockpit_report_payload_templates`;
- report delivery accepts `channel` and `template_id`;
- the rendered payload is returned in API response;
- the rendered payload has channel, capability, resource ref, and constraints;
- the cross-plane execution receipt action uses the rendered payload;
- idempotent replay returns the same cross-plane receipt and does not duplicate
  delivery receipts.

## Next Version

`v0.9.95` should add a report schedule/job runner that can select due cockpit
profiles, generate report snapshots, and optionally enqueue governed delivery
requests through the same payload and cross-plane path.
