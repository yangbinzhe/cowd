# v0.9.275-v0.9.282 Matrix/MFG/WebUI Full Refactor Plan

## Status

This plan supersedes the compatibility-oriented v0.9.270-v0.9.274 migration plan, which is archived at `docs/archive/plans/v0.9.270-matrix-memory-mfg-webui-evolution.md`. Earlier IACC-era phase plans are also archived under `docs/archive/plans/` and are historical records, not executable guidance.

The new target is a destructive full migration:

- No `iacc`, `Iacc`, `IACC`, `/api/iacc`, `iacc.sqlite`, `iacc_*`, `IaccPage`, or `iaccWriteContracts` remains.
- Existing implemented IACC capabilities are not rebuilt. They are moved, renamed and reassigned by responsibility.
- Matrix becomes the structured fact engine kernel.
- Memory remains the unstructured fact engine kernel.
- Matrix and Memory become the two fact engines used by context, agents, skills, tools and governance.
- MFG becomes the manufacturing application layer over Matrix, Memory and runtime contracts.
- WebUI becomes a shell plus plugins. MFG pages are plugin-owned pages, not shell-owned pages.
- Rust default builds do not copy, compile or require WebUI assets.

## Non-Negotiable Rules

1. No compatibility facade:
   - Delete `runtime::iacc`.
   - Delete `/api/iacc/*`.
   - Delete `Iacc*` public types.
   - Delete `iacc.sqlite` as a live runtime store name.
   - Delete `IaccPage.vue` and `iaccWriteContracts.json`.

2. Move before inventing:
   - Existing behavior must be inherited by file movement and symbol rename.
   - New implementations are allowed only for missing boundaries, contracts, routing, storage naming, plugin loading and Matrix/Memory fusion.

3. Responsibility decides destination:
   - Matrix owns structured facts, entities, relations, metrics, evidence, lineage, source packs, quality gates, data-plane ingestion and compute jobs.
   - Memory owns unstructured memory, semantic recall, vector-backed retrieval and generic case-materialization contracts.
   - MFG owns manufacturing domains, ontology packs, incidents, operational analysis, action execution, playbooks, cockpit/reporting and manufacturing skills.
   - WebUI shell owns app frame, navigation, session surfaces, generic runtime pages and plugin host contracts.
   - MFG WebUI plugin owns manufacturing pages, MFG API calls and MFG-specific contracts.

4. Tests define completion:
   - A phase is not complete until its naming, boundary, API, storage and build gates pass.
   - `rg -i "iacc" crates webui scripts docs/operator docs/architecture docs/api docs/developer` over existing paths must return no active product references by the final phase.
   - Migration plans that must mention old names are archived before the final product scan and are excluded only by explicit release policy.

## Final Architecture

```text
kernel
  runtime
  matrix                 # structured fact engine
  memory                 # unstructured fact engine
  context                # Matrix + Memory evidence fusion
  skills/tools/agents
  cross-plane/governance

apps
  mfg                    # manufacturing application module/crate

surfaces
  tui
  webui-shell
  webui-plugin-mfg
```

Dependency rules:

```text
matrix -> runtime primitives only
memory -> runtime primitives only
context -> matrix traits + memory traits
mfg -> matrix + memory + runtime + skills/tools/cross-plane contracts
webui-shell -> plugin manifest contract + generic API client
webui-plugin-mfg -> MFG API contract
runtime default build -> no Node/Vite/WebUI asset requirement
```

Forbidden dependency rules:

```text
matrix must not import or mention mfg, manufacturing, cockpit, incident, playbook, webui
memory must not import or mention mfg, manufacturing, webui
mfg must not be imported by matrix or memory
webui-shell must not directly import MFG page components
```

## Phase v0.9.276 - Build Decoupling and Migration-Safe WebUI Asset Policy

Goal:
Stop Rust builds from amplifying WebUI path/name churn before the WebUI shell/plugin split.

Steps:

1. Update `cowd-cli/build.rs`:
   - default: no WebUI copy into `crates/cowd-cli/static`.
   - default: no WebUI copy into `target/{profile}/webui`.
   - opt-in feature/env only: embedded or copied WebUI assets.
2. Update runtime static serving:
   - daemon serves WebUI only when `COWD_WEBUI_DIR` or explicit packaged asset dir exists.
   - fallback behavior must not silently serve stale source-tree assets.
3. Add generated asset cleanup policy:
   - `webui/assets/app/*` generated bundles are not source of truth.
   - service worker caches and generated manifests must be regenerated after MFG plugin split or removed from active scans.
4. Add package/install checks:
   - `cargo check -p cowd-cli`
   - `cargo package -p cowd-cli --allow-dirty` or equivalent package dry run
   - daemon startup diagnostics with no WebUI dir
   - daemon startup diagnostics with explicit `COWD_WEBUI_DIR`

Acceptance:

- Rust default check/build/package does not require WebUI files, Node or Vite.
- Removing or renaming local `webui/node_modules` does not affect Rust build.
- Static WebUI serving is explicit and observable in diagnostics.
- Generated WebUI assets are not copied by default during Rust builds.

Risk controls:

- Runtime serving support remains available through explicit configuration.
- This phase changes build coupling only, not WebUI page behavior.
