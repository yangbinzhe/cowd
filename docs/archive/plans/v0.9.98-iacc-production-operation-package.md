# v0.9.98 IACC Production Operation Package

## Goal

Close the current IACC implementation batch by turning the implemented kernel into an operable production package: versioned readiness, operator runbook, release gate, and an end-to-end validation chain from data ingest to cockpit report visibility.

## Completed Scope

- IACC health declares `production_operation_package`, so operators can detect that this build includes the production runbook and release gate.
- `docs/operator/iacc-production-runbook.md` defines the production onboarding, operation, governance, validation, and rollout model.
- `scripts/v0998_iacc_production_release_gate.sh` provides a repeatable release gate for Rust formatting, backend tests, build, IACC scenario chain, and optional strict WebUI unit tests.
- The gate covers the implemented IACC chain:
  - foundation fact ingest and evidence packet creation
  - metric attention and recompute
  - evidence-agent context
  - operational analysis
  - action feedback closure
  - entity relation network
  - server manufacturing domain pack
  - metric dependency graph
  - incremental compute job
  - scale benchmark
  - quality gates
  - cross-plane action bridge
  - personal cockpit projection
  - cockpit report snapshot
  - report delivery bridge
  - payload templates
  - schedule runner
  - delivery retry state
  - WebUI report visibility

## Production Readiness Contract

An IACC build is production-ready only when these checks are true:

- The gateway exposes `GET /api/iacc/health` with schema version `11` and capability `production_operation_package`.
- The release gate exits `0` in a clean working tree or CI runner.
- The operator can load the WebUI and see the IACC panel entry and report state controls.
- The operator can create a cockpit profile, create or schedule a report, inspect delivery state, and retry delivery through governed cross-plane routes.
- A production data onboarding pack exists for each source system, including ownership, source access mode, entity mapping, fact mapping, metric impact, reconciliation rule, freshness SLA, and fallback handling when no API exists.

## How To Run

```bash
TMPDIR=/media/yi/Ext/cowd-build-tmp \
CARGO_TARGET_DIR=/media/yi/Ext/cowd-iacc-release-target \
scripts/v0998_iacc_production_release_gate.sh
```

For CI or a release machine with WebUI dependencies installed, force WebUI unit tests:

```bash
IACC_V0998_REQUIRE_WEBUI_TESTS=1 scripts/v0998_iacc_production_release_gate.sh
```

To skip the expensive scale benchmark during inner-loop development:

```bash
IACC_V0998_SKIP_SCALE_BENCHMARK=1 scripts/v0998_iacc_production_release_gate.sh
```

## Acceptance Result

v0.9.98 is accepted when:

- `cargo fmt --all --check` passes.
- `cargo test -p cowd-cli iacc --no-default-features -- --test-threads=1` passes.
- `cargo build -p cowd-cli --no-default-features` passes.
- `scripts/v0998_iacc_production_release_gate.sh` passes.
- A tag `v0.9.98` is created with a Chinese release explanation.

## Not Included

- Live ERP/MES/PLM/SRM/WMS credentials.
- A production external warehouse or stream processor.
- Browser E2E screenshots for the IACC panel.
- Real Feishu/enterprise-channel commit dispatch; current scenarios remain governed dry-run unless configured by the operator.

These are deployment-specific and must be provided by the production operator pack described in the runbook.
