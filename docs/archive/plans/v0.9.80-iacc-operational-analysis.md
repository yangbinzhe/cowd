# v0.9.80 IACC 运营归因、影响路径与处置建议

## 版本定位

`v0.9.80` 在 `v0.9.79` 的 evidence/context/agent 链路之上，补齐从“发现问题”到“形成可审查处置方案”的确定性结构化分析能力。

本版本仍不依赖 LLM 临场生成结论，而是用 evidence packet 中的 metric/change 证据生成 typed attribution、impact path 和 recommended action，并持久化为 IACC operational analysis。这样后续版本可以把 recommended action 接入治理、执行和闭环反馈。

## 核心能力

- 新增 `IaccOperationalAnalysis`。
- 新增 `IaccAttributionCandidate`。
- 新增 `IaccImpactPath`。
- 新增 `IaccRecommendedAction`。
- Incident 可触发结构化分析。
- 分析结果会回写 EvidencePacket：
  - `attribution_candidates`
  - `impact_paths`
  - 移除 `attribution_not_computed` 和 `impact_paths_not_computed` 缺口。
- Incident 分析完成后状态更新为 `analyzed`。

## API

- `POST /api/iacc/incidents/:id/analyze`
- `GET /api/iacc/analyses/:id`

`GET /api/iacc/health` 新增：

- `analysis_count`
- capability: `incident_operational_analysis`

## 规则边界

当前版本采用可解释的 deterministic rule：

- `material_shortage_risk` 或 `component:*` 实体归因为 `supply_constraint`。
- `plan_bom_delta`、`demand`、`bom` 类指标归因为 `planning_demand_change`。
- `quality` 类指标归因为 `quality_escape`。
- `capacity` 类指标归因为 `capacity_constraint`。
- 无法识别的指标进入 `metric_delta` 或 `evidence_gap`。

推荐动作均带有：

- `action_type`
- `owner_role`
- `priority`
- `expected_effect`
- `required_evidence`
- `command_hint`
- `governance`

所有动作默认 `human_review_required`，为下一版本的治理执行闭环预留接口。

## 验收

新增脚本：

- `scripts/v0980_iacc_operational_analysis_scenario.sh`

脚本验证：

- gateway 启动。
- IACC schema version 为 4。
- fact ingest、metric recompute、attention、evidence、incident 均正常。
- incident analyze 返回 attribution、impact、recommended action。
- GPU shortage 场景归因为 `supply_constraint`。
- 影响路径为 `material_availability_risk`。
- 推荐动作为 `supplier_recovery`。
- analysis 可回查。
- incident 状态更新为 `analyzed`。
- evidence packet 写回 attribution 和 impact path。

## 与 v0.9.79 的区别

`v0.9.79` 解决运营问题如何进入现有 AI 大脑和多智能体任务图。

`v0.9.80` 解决进入任务图之后，IACC 如何基于结构化证据生成稳定、可审查、可执行前置的业务分析结论。
