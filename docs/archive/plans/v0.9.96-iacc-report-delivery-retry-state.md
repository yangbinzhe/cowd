# v0.9.96 IACC Report Delivery Retry State

## Goal

`v0.9.96` adds typed delivery-state classification and a controlled retry
entrypoint for cockpit report delivery. Operators can now inspect why a report
delivery is blocked or failed, then intentionally retry with a new idempotency
key after the missing identity, grant, target, or adapter condition is fixed.

## Scope

- Add `IaccCockpitReportDeliveryState`.
- Add `GET /api/iacc/cockpit/reports/:id/delivery-state`.
- Add `POST /api/iacc/cockpit/reports/:id/delivery/retry`.
- Classify report delivery attempts as:
  - `not_delivered`;
  - `policy_blocked`;
  - `delivery_blocked`;
  - `dry_run_planned`;
  - `awaiting_human_review`;
  - `sent`;
  - `delivery_retryable_failure`.
- Generate retry idempotency keys as:

```text
iacc-retry:{report_id}:{latest_cross_plane_receipt_id}:{attempt_count + 1}
```

- Require `force=true` when retrying a non-retryable state such as
  `policy_blocked`.
- Reuse the same payload template and cross-plane bridge path as normal
  delivery.

## API Contract

State:

```http
GET /api/iacc/cockpit/reports/{id}/delivery-state
```

Retry:

```json
{
  "force": true,
  "mode": "dry_run",
  "actor_principal": "user:ops-planner",
  "actor_identity_ref": "iacc://operator/ops-planner",
  "channel": "feishu",
  "template_id": "ops.alert.compact"
}
```

Response contains:

- `before_state`;
- `after_state`;
- full delivery outcome.

## Acceptance

`scripts/v0996_iacc_report_delivery_retry_state_scenario.sh` validates:

- health advertises `cockpit_report_delivery_retry_state`;
- initial report delivery without identity/grant becomes `policy_blocked`;
- delivery state reports `retryable=false`;
- force retry after identity/grant setup creates a new cross-plane receipt;
- after-state becomes `dry_run_planned`;
- delivery receipt count increases to two without losing the blocked attempt.

## Next Version

`v0.9.97` should surface cockpit report delivery state in WebUI/runtime
contracts so operators can inspect generated reports, payloads, delivery
attempts, and retry posture without using raw API calls.
