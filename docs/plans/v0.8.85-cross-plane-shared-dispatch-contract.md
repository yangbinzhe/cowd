# v0.8.85 Cross-Plane Shared Dispatch Contract

## Goal

Move dispatch target planning out of the API route layer and into the runtime
cross-plane contract. The dispatch target is now part of the shared policy and
execution receipt model instead of an API-private JSON snapshot.

## Design

- `CrossPlaneDispatchTarget` is the stable runtime contract for target readiness.
- `CrossPlaneOutboundMessagePlan` is the stable runtime contract for outbound
  message execution input.
- `CrossPlaneExecutionReceipt.dispatch_target` stores the typed target snapshot.
- API preflight and execution responses keep the same JSON shape for WebUI and
  TUI compatibility.
- Target parsing remains non-panicking and returns explicit blockers:
  `dispatch:target_ref_missing`, `dispatch:target_ref_invalid`,
  `dispatch:payload_text_missing`, and related dispatch diagnostics.

## TDD Acceptance

- Runtime can build a ready text dispatch target from a channel target ref.
- Runtime reports missing target refs without panicking.
- Execution receipts round-trip typed dispatch target state through JSON.
- API preflight still returns the existing dispatch target JSON contract.
- API dry-run execution still persists dispatch target snapshots in receipts.

## Follow-Up

The next valuable step is a live dispatch executor that consumes
`CrossPlaneOutboundMessagePlan`, routes through bound platform adapters, and
records dispatched/failed receipt states with provider message IDs.
