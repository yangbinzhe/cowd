# Cowd v0.8.21 Runtime Event Spine And Agent Value Loop Plan

v0.8.21 focuses on closing the runtime loop instead of adding broad new
surfaces. The goal is to make task, agent, context, and memory decisions visible
through one event spine, then use measurable value signals to decide when
multi-agent collaboration is worthwhile.

## Design Target

- Task lifecycle changes are canonical `RuntimeEvent`s.
- Task records remain available through the existing API shape, backed by
  SQLite task storage and projected into the unified session event log.
- Agent collaboration emits a deterministic value verdict derived from the
  existing scorecard.
- Runtime control policy uses collaboration thresholds and parallel-agent limits
  during actual routing.
- WebUI/TUI/API can explain the latest task, policy, workgraph, and collaboration
  value decisions without recomputing core policy.

## Phase 1: Task Runtime Event Spine

Every task mutation should append a runtime event under `session_id = task.id`.

Events:

- `task.started`
- `task.phase.started`
- `task.phase.artifact.recorded`
- `task.phase.reviewed`
- `task.failure.recorded`
- `task.blocked`
- `task.cancelled`
- `task.completed`

Acceptance:

```bash
cargo test -p cowd-cli task_api_records_phase_artifacts_and_review -- --nocapture
cargo test -p cowd-cli task_api_starts_reports_and_blocks_after_repeated_failures -- --nocapture
```

## Phase 2: Agent Value Loop

Add a deterministic collaboration value verdict:

- `positive_lift`
- `continue_multi_agent`
- `value_score`
- `reasons`

The verdict is written into `agent.workgraph.reviewed` payloads and projected
through runtime summary APIs.

Acceptance:

```bash
cargo test -p runtime scorecard_value_verdict -- --nocapture
cargo test -p cowd-cli runtime_timeline_projects_workgraph_summary -- --nocapture
```

## Phase 3: Scenario Policy Routing

Make configured collaboration thresholds and parallel-agent limits affect actual
routing. A profile may still recommend review context while refusing parallel
agents when the value threshold or max-agent limit does not justify them.

Acceptance:

```bash
cargo test -p runtime runtime_control -- --nocapture
```

## Phase 4: Runtime Cockpit Projection

Expose task events and collaboration value verdicts through existing runtime
timeline and WebUI runtime console components.

Acceptance:

```bash
cd webui && npm test
```
