# v0.8.82 Cross-Plane Dispatch Target Plan

## Goal

Make cross-plane execution plans concrete before enabling live sends. Every
preflight and execution response should expose where a channel action would be
sent, which operation it would use, which payload is available, and which
dispatch prerequisites are still missing.

## Design

- Add a `dispatch_target` envelope to cross-plane preflight and execution
  responses.
- Resolve target sessions from stable refs:
  - `channel://platform/user/id/thread/id`
  - `channel://platform/chat/id`
  - `platform:user[:thread]`
- Extract `send_text` payloads from `text://...`, `text:...`, or plain text
  resource refs.
- Keep file/image resource refs in the outbound plan metadata until adapters
  have operation-specific send support.
- In commit mode, distinguish:
  - `adapter_not_bound`: runtime adapter is not connected.
  - `dispatch_target_not_ready`: adapter is connected but target/payload is
    incomplete.
  - `dispatch_not_implemented`: target is ready, but live dispatch is still
    intentionally disabled.

## Acceptance

- Preflight returns a ready dispatch target for a valid Feishu text action.
- Preflight exposes missing target blockers without crashing or consuming
  grants.
- Commit execution blocks on target readiness before reaching live dispatch.
- Existing dry-run, idempotency, policy, audit, and adapter readiness behavior
  remains stable.

## Follow-Up

- Add a live dispatch executor that turns the approved plan into
  `OutboundMessage` and calls `PlatformRuntime::send_response`.
- Persist dispatch target snapshots in execution receipts for stronger replay
  observability.
- Add WebUI/TUI rendering for dispatch target readiness and blockers.
