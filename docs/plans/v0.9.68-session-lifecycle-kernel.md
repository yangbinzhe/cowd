# v0.9.68 Session Lifecycle Kernel

## Goal

Make session lifecycle a first-class daemon runtime concept without forcing
model/provider initialization for control-plane operations.

## Implemented Scope

- Added `SessionLifecycleKernel` for in-memory session attachment state.
- Added explicit lifecycle states: created, active, attached, detached, idle,
  suspended, restored, closing, closed, failed.
- Added lifecycle events with per-session monotonic sequence numbers.
- Added actor-aware attach/detach snapshots for TUI, WebUI, and socket clients.
- Added socket commands:
  - `session.attach`
  - `session.detach`
  - `session.lifecycle`
  - `session.replay`
- Added lifecycle data to `runtime.snapshot`.
- Added replay projection through the existing `UnifiedSessionStore` event page
  API with cursor and limit.

## Non-Goals

- This version does not enforce writer lease on every chat/task operation yet.
- It does not persist lifecycle attachment metadata as authoritative DB state;
  durable replay still uses the existing session event log.

## Validation

- Unit tests cover attach dedupe, detach behavior, monotonic concurrent
  sequence allocation, runtime service projection, and protocol aliases.
- `scripts/v0968_session_lifecycle_scenario.sh` starts a real daemon, connects
  over the Unix socket, verifies attach/detach/lifecycle/replay, and confirms
  lifecycle data appears in `runtime.snapshot`.
