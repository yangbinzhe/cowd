# v0.8.76 Cross-Plane Execution Envelope

## Goal

Move cross-plane actions from policy-only management into a safe execution
envelope. The system must expose one stable lifecycle for UI, TUI, channels,
agents, and future service adapters:

1. resolve actor identity;
2. evaluate grants and policy;
3. verify target platform readiness;
4. produce an execution plan;
5. record audit evidence;
6. block live dispatch when no real adapter is bound.

## Design

- `POST /api/cross-plane/action/preflight` remains side-effect free.
- `POST /api/cross-plane/action/execute` accepts `{ mode, idempotency_key, action }`.
- `mode: dry_run` returns a planned execution and records a dry-run audit event.
- `mode: commit` is explicit, but currently blocks with
  `dispatch:adapter_not_bound` until a real adapter is registered.
- No endpoint consumes a single-use grant unless an actual committed dispatch
  path exists. This avoids losing approvals on failed or fake delivery.

## Acceptance

- Dry-run execution returns `kind=cross_plane_action_execution`,
  `status=planned`, and `dispatch_status=dry_run`.
- Commit execution without a live adapter returns `status=blocked` and
  `dispatch_status=adapter_not_bound`.
- Both paths write audit records.
- Dry-run and blocked commit preserve single-use grants.
- WebUI API exposes the execution endpoint.
