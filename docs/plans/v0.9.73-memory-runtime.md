# v0.9.73 Memory Runtime

## Goal

Make memory a practical runtime substrate for session, agent, and context execution without adding a heavy parallel architecture.

## Implemented Scope

- Added authority decisions for effective knowledge:
  - higher-authority memory supersedes older facts;
  - equal-authority disagreement becomes explicit conflict;
  - duplicate facts remain observed instead of rewriting history.
- Added bounded memory clusters for large projects and document sets:
  - cluster by stable topic key;
  - expose summary, tokens, hotness, tags, and truncation;
  - avoid loading full large bodies into runtime display.
- Added context usage feedback:
  - selected memory atoms are recorded as usage signals;
  - repeated selections mark hot memories;
  - selected active/observed memories become validated through lifecycle events.
- Added runtime API and WebUI presentation:
  - `/api/memory/runtime`;
  - `/api/memory/clusters`;
  - `/api/memory/lifecycle/:id`;
  - Memory panel shows living runtime metrics and top clusters.
- Added real gateway scenario:
  - starts gateway with memory enabled;
  - writes real memory entries through API;
  - verifies context recall, runtime snapshot, clusters, lifecycle, and WebUI static delivery.
