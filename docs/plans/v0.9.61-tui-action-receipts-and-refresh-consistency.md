# v0.9.61 TUI Action Receipts And Refresh Consistency

## 目标

让 TUI 中由用户触发的 daemon/task/approval/connector/memory 动作形成统一、可见、可追踪的最近执行回执，避免动作只靠 toast 短暂提示，后续刷新后用户无法确认系统状态。

## 实施内容

- 新增 `RuntimeActionReceiptSummary`，作为 TUI runtime control 的统一动作回执模型。
- `App` 保存最近 runtime action receipts，`GatewayPanel` 从 App 同步并展示。
- 以下动作写入回执：
  - daemon approval approve/reject。
  - daemon task cancel/complete。
  - connector resource revalidate。
  - connector resource promote to memory。
- 回执保留最近 8 条，并截断过长状态，避免 TUI 行宽失控。

## TDD 验收

1. `snapshot_round_trips_action_receipts_through_app`：验证 snapshot/app 不丢回执。
2. `connector_resource_actions_prefer_socket_control`：验证 socket 动作后 App 与 GatewayPanel 均有回执。
3. `runtime_action_receipt_truncates_long_status`：验证错误状态不会撑爆 TUI。
4. `cargo fmt --check` 与 `git diff --check` 必须通过。

## 评价标准

- 动作执行结果从短暂 toast 变为可见的 Runtime Command Center 状态。
- 局部动作后本地 UI 立即一致，不等待下一轮 HTTP projection。
- 实现保持轻量，不引入新的后台状态机。
