# v0.9.62 TUI Runtime Control Store Layering

## 目标

降低 `TuiState` 对 runtime control 本地状态的直接修改复杂度，把 approval/task/resource/receipt 这些局部一致性操作收敛到轻量 store 层，为后续继续扩展 TUI 控制能力留出清晰边界。

## 实施内容

- 新增 `RuntimeControlLocalStore`。
- Store 从 `App` 读取 `RuntimeControlSnapshot`，执行局部 mutation 后再应用回 `App`。
- 收敛以下本地一致性操作：
  - approval response 后移除 pending approval。
  - task cancel/complete 后更新任务状态。
  - connector resource revalidate 后更新 indexed state。
  - runtime action receipt 追加、截断与保留最近 8 条。
- `TuiState` 只负责调用 store 和同步组件，不再直接散落修改这些字段。

## TDD 验收

1. `local_store_applies_runtime_mutations_and_receipt_limits`：验证 store 能完成 approval/task/resource/receipt mutation 并保护字段长度。
2. `connector_resource_actions_prefer_socket_control`：验证真实 TUI action 路径仍能更新资源状态和回执。
3. `cargo fmt --check` 与 `git diff --check` 必须通过。

## 评价标准

- runtime control 本地变更逻辑有单一入口。
- 后续新增 TUI 控制动作时优先扩展 store，而不是继续扩大 `state.rs`。
- 不改变现有 App 数据结构对组件的同步方式，降低回归风险。
