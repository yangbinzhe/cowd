# v0.8.13 Intelligent Context Runtime Framework

## Version Goal

v0.8.13 的目标是把 Cowd 的 context 从“每轮拼接 prompt 的辅助逻辑”升级为“AI 运行时的一等基础设施”。

它必须统一支撑：

- 主对话 turn context。
- `/solo`、`--yolo`、连续任务、任务 phase、cron 等执行模式。
- sub-agent、collaboration、JPS、wave 等 agent 自主委托。
- session resume、handoff、compact、memory recall、tool trace、workspace/project knowledge。
- TUI/WebUI/API 对 context 状态、压力、来源、预算、裁剪原因的透明展示。

最终目标：

```text
Intent -> ContextEnvelope -> Model/Agent Action -> Trace -> Memory/Session/Task Update -> Next Envelope
```

Context 不再是字符串，而是可解释、可治理、可预算、可继承、可回传、可观测的运行时对象。

## Current Reality

现有能力已经很强，但仍分散。

### Already Strong

- `ConversationRuntime` 每轮会调用 `prepare_memory_context()`。
- `MemoryKernel` 已经成为 memory prepare/post_turn/remember/archive 的治理边界。
- `MemoryTurnContext` 已有 session/agent/project/team/task 绑定字段。
- `CognitiveContextManager.prepare_context()` 已有：
  - L0/L1/L2 固定层。
  - L3 动态召回。
  - L4 team query / event bus。
  - seeds、code symbols、KG、cache、coherence、budget、performance metrics。
- `run_memory_post_turn()` 已经能在 turn 后抽取、压缩、漂移检测、维护索引。
- session store 已经 DB-first，具备 session/events/messages。
- handoff、fresh context、state rebuilder 已存在。
- sub-agent runtime 会继承 parent memory manager。
- collaboration synthesis 会写入 L4 shared memory。
- TUI/WebUI 已开始展示 session、task、memory packet、links、knowledge network。

### Core Gaps

- Context 没有统一对象模型。当前最终仍是 `Vec<String>` system prompt。
- 主对话、sub-agent、collaboration、JPS、wave 各自决定如何取 context，缺少统一策略。
- `MemoryTurnContext` 是 memory 边界上下文，不是完整 runtime context。
- context budget 只在 memory 层和 auto-compact 局部处理，没有全局 token lease。
- tool outputs 被排除在 long-term memory 外是合理的，但缺少短期 tool trace context 的结构化管理。
- agent 委托缺少 ContextLease：
  - parent 给子 agent 哪些事实。
  - 子 agent 可见哪些 memory。
  - 子 agent 需要回传哪些 trace/decision/artifact。
  - 子 agent 失败时 parent 如何恢复。
- context fence 只过滤 memory entry，不治理工具结果、session history、task state、workspace evidence。
- context pressure 目前主要触发 compaction，未形成“降级但不中断”的智能调度。
- UI 只能看到 memory/status，不能看到完整 ContextEnvelope 的来源、预算、裁剪和风险。

## Design Principles

### 1. Context Is A Runtime Contract

ContextEnvelope 必须是模型调用前的唯一入口对象，替代散落在 runtime/memory/agent 中的临时拼接。

它包含：

- intent：本轮用户目标或 agent 子目标。
- identity：session/project/agent/team/task/mode。
- policy：权限、隔离、可见性、写入规则、yolo/solo 行为。
- sources：conversation、memory、task、tool trace、workspace、handoff、agent peer context。
- budget：每类来源的 token lease。
- packet：最终进入 model 的有序内容。
- omissions：未注入内容及原因。
- diagnostics：pressure、degraded path、cache hit、latency、risk。

### 2. Context Has Lifecycle

```text
Acquire -> Select -> Rank -> Lease -> Assemble -> Execute -> Observe -> Distill -> Reconcile
```

- Acquire：从 session DB、MemoryKernel、task registry、workspace、tool trace、handoff 取候选。
- Select：按 mode/agent/session fence 过滤。
- Rank：按 intent、authority、recency、confidence、dependency、risk 评分。
- Lease：分配 token 和可见性，不让某一类来源挤爆全局。
- Assemble：生成 provider-ready prompt/messages。
- Execute：模型/agent/tool 执行。
- Observe：记录 context_event 和使用情况。
- Distill：turn 后写入 memory/session/task。
- Reconcile：处理冲突、supersession、handoff、resume。

### 3. One Context Kernel, Multiple Context Profiles

新增 `ContextRuntimeKernel`，对不同执行模式使用 profile，而不是复制逻辑。

| Profile | Use Case | Bias |
| --- | --- | --- |
| `MainTurn` | 普通主对话 | 高连续性，高用户意图权重 |
| `SoloGoal` | `/solo` | 强任务状态，低打断，高验收 |
| `YoloGoal` | `--yolo` 连续执行 | 最大自动推进，强恢复和审计 |
| `SubAgent` | agent 委托 | 最小必要上下文，明确边界 |
| `Collaboration` | 多 agent 综合 | peer memory、conflict、decision trace |
| `Review` | 阶段审查 | evidence、diff、tests、acceptance |
| `Resume` | 会话接续 | handoff、task graph、recent decisions |
| `Cron` | 后台定时任务 | 无交互、强权限和输出约束 |

### 4. Budget Is A Lease, Not A Limit

全局 context budget 应拆成可动态调整的 lease：

- system/instructions
- active conversation
- pinned facts
- memory orientation packet
- task state
- tool trace summary
- workspace/code evidence
- peer agent packets
- response reserve

当压力升高时，不应只 compact，而应逐级降级：

1. 精简 tool trace。
2. 降低 peer packet 数量。
3. 从 raw memory entry 改为 context packet。
4. conversation 变为 rolling summary + recent turns。
5. 写 handoff，并建议 session boundary。

### 5. Agent Context Must Be Inherited And Returned

Sub-agent 不应直接复制 parent prompt。

它应拿到：

- parent intent 摘要。
- agent-specific task contract。
- scoped memory packet。
- allowed tools / permissions。
- required return schema。
- evidence requirements。
- failure/retry policy。

Sub-agent 完成后必须回传：

- result summary。
- evidence/artifacts。
- decisions。
- discovered conflicts。
- memory candidates。
- next actions。

Parent 再由 ContextRuntimeKernel 统一 reconcile，而不是让 collaboration 直接写散点 memory。

## Target Architecture

```text
ConversationRuntime
  -> ContextRuntimeKernel
       -> ContextIdentity
       -> ContextProfile
       -> ContextPolicy
       -> ContextAcquirer
            - SessionStoreSource
            - MemoryKernelSource
            - TaskRegistrySource
            - ToolTraceSource
            - WorkspaceSource
            - AgentPeerSource
            - HandoffSource
       -> ContextRanker
       -> ContextBudgeter
       -> ContextAssembler
       -> ContextObserver
  -> Provider Request
  -> ContextRuntimeKernel::post_turn(...)
       -> Session events
       -> MemoryKernel::post_turn
       -> Task/Agent trace updates
       -> Context metrics
```

## Source Integration

### Session Source

Uses `UnifiedSessionStore` and current in-memory `Session`.

Provides:

- recent user/assistant messages.
- pinned messages.
- compacted session summary.
- event timeline references.

Needed changes:

- stop treating old JSONL as context source.
- expose `SessionContextPacket` with recent, pinned, summary, omissions.

### Memory Source

Uses `MemoryKernel`.

Provides:

- `MemoryContextPacket` instead of raw entries.
- layer projections.
- links/path recall.
- lifecycle state: active/superseded/archived.

Needed changes:

- make `MemoryKernel.context_packet()` the default runtime injection path.
- keep raw entry injection only as debug/diagnostic fallback.

### Task Source

Uses task registry and durable task phases.

Provides:

- active task objective.
- current phase.
- acceptance criteria.
- blockers.
- test commands.
- latest review result.

Needed changes:

- task phase context packet.
- yolo/solo should always receive active task packet.

### Tool Trace Source

Uses session event log and tool execution summaries.

Provides:

- recent tool results.
- failed commands.
- modified files.
- test output summary.

Needed changes:

- store tool trace as bounded structured packet.
- never inject huge raw outputs.
- allow drilldown via tool/event IDs.

### Agent Peer Source

Uses L4 shared memory, agent directory, collaboration outputs.

Provides:

- peer capabilities.
- peer synthesis.
- conflicting claims.
- open delegation results.

Needed changes:

- sub-agent return schema.
- parent/child context trace.
- peer packet budget.

### Workspace Source

Uses existing file/code tooling, project KG, hot symbols.

Provides:

- relevant symbols.
- touched files.
- project conventions.
- workspace state summary.

Needed changes:

- workspace packet should be acquired through ContextRuntimeKernel, not appended ad hoc.

## TDD Implementation Plan

## Phase 1: Context Types And Envelope Builder

### Objective

Create the runtime object model without changing provider behavior.

### Work

- Add `crates/runtime/src/context_runtime.rs`.
- Define:
  - `ContextIdentity`
  - `ContextMode`
  - `ContextProfile`
  - `ContextEnvelope`
  - `ContextItem`
  - `ContextLease`
  - `ContextDiagnostics`
- Add `ContextRuntimeKernel::build_envelope(...)`.
- Initially wrap current `prepare_memory_context()` output into an envelope.

### Tests

- envelope has stable identity.
- envelope can represent main turn and sub-agent turn.
- envelope never panics when memory/session/task source is absent.
- diagnostics record degraded sources.

### Acceptance

- No behavior regression.
- Provider request still receives same effective prompt.
- New envelope can be serialized for WebUI/TUI diagnostics.

## Phase 2: Memory Packet First Injection

### Objective

Replace raw memory entry prompt assembly with `MemoryContextPacket`.

### Work

- `MemorySource` calls `MemoryKernel.context_packet()`.
- Preserve current layer tags as role metadata.
- Convert selected/omitted into `ContextItem`/`ContextOmission`.
- Inject packet in deterministic order:
  - orientation
  - warnings/conflicts
  - supporting facts
  - links/path hints

### Tests

- archived/superseded memory is not injected.
- omitted memory records reason.
- context stays below memory lease.
- degraded memory returns base prompt, not error.

### Acceptance

- Existing memory tests stay green.
- WebUI packet view matches runtime packet.

## Phase 3: Global Budget Lease

### Objective

Introduce budget governance across all context sources.

### Work

- Add `ContextBudgeter`.
- Define default leases per profile.
- Apply leases before assembly.
- Record pressure and degradation steps.

### Tests

- main turn preserves recent conversation before low-priority peer context.
- yolo profile preserves task/acceptance/test context.
- sub-agent profile receives smaller context than parent.
- overload produces omissions, not oversized prompt.

### Acceptance

- `model_context_window` becomes real budget input.
- auto-compaction becomes one degradation action, not the only response.

## Phase 4: Agent Context Lease And Return Packet

### Objective

Make sub-agent context explicit, isolated, and useful.

### Work

- Add `AgentContextLease`.
- Add `AgentReturnPacket`.
- `create_subagent_runtime()` receives a child `ContextIdentity`.
- Collaboration/JPS/wave use context leases.
- Child writes go through `MemoryKernel` with child agent ID and parent task/session ID.

### Tests

- child context includes task contract but not unrelated parent turns.
- child memory writes have child `source_agent`.
- parent receives child return packet and writes one reconciled L4 synthesis.
- failed child returns trace without corrupting parent envelope.

### Acceptance

- Multi-agent runs are auditable as parent/child context spans.
- Peer context is useful but bounded.

## Phase 5: Tool Trace And Workspace Packets

### Objective

Preserve tool usefulness without flooding context.

### Work

- Add bounded `ToolTracePacket`.
- Add `WorkspacePacket`.
- Extract recent changed files, failed tests, commands, evidence IDs.
- Keep raw output out of prompt unless explicitly needed.

### Tests

- large tool output is summarized and referenced.
- failed test summary is preserved across next turn.
- file modifications are visible in review profile.
- packet has drilldown IDs.

### Acceptance

- Review/debug turns get the evidence they need.
- Long command outputs no longer crowd out intent.

## Phase 6: Resume/Handoff Context Recovery

### Objective

Session continuation restores active context graph, not just messages.

### Work

- Build `Resume` profile.
- Pull:
  - latest handoff.
  - active task phases.
  - last decisions.
  - compacted summary.
  - recent memory orientation.
- Do not auto-import JSONL.

### Tests

- resume envelope includes task phase and handoff.
- stale handoff is lower priority than active DB task state.
- missing handoff is nonfatal.
- JSONL never participates unless explicitly imported.

### Acceptance

- Long-running yolo/solo can stop and resume with coherent working state.

## Phase 7: UI/API Observability

### Objective

Expose context intelligence to users.

### Work

- API:
  - `GET /api/context/current`
  - `GET /api/context/:envelope_id`
  - `GET /api/sessions/:id/context`
- WebUI:
  - context budget bars.
  - source packets.
  - omissions and reasons.
  - agent parent/child context spans.
- TUI:
  - context pressure indicator.
  - source counts.
  - compact/handoff recommendations.

### Tests

- API returns envelope DTO.
- WebUI renders degraded source and omissions.
- TUI state shows context pressure without blocking turn execution.

### Acceptance

- Users can see why the AI remembered, omitted, or compressed something.

## Governance Rules

- Runtime must never fail a turn because one context source failed.
- Every omission must have a reason.
- Every child agent must have a parent context span.
- Memory writes must go through `MemoryKernel`.
- JSONL must not be an active context source.
- Raw tool output must not enter context unless explicitly selected.
- Context assembly must be deterministic for the same inputs.
- UI must show pressure and degradation, not hide them.

## Recommended First Implementation Cut

The safest high-value first cut is:

1. Add `ContextEnvelope` and diagnostics without changing prompt output.
2. Route memory through `MemoryContextPacket`.
3. Add budget lease and omissions.
4. Add WebUI/TUI context diagnostics.
5. Then refactor sub-agent lease and return packets.

This order keeps behavior stable while creating the architecture needed for more intelligent runtime context.
