# Cowd v0.8.22 Runtime Health Projection Plan

v0.8.22 keeps the runtime architecture lean. It does not add another control
plane. It projects the existing runtime event spine into one health signal that
API, WebUI, TUI, and future schedulers can consume.

## Design Target

- Runtime timeline responses include a deterministic `health_summary`.
- Health uses existing event facts only: status, scope, kind, workgraph value
  verdict, task lifecycle events, and degraded/corrupt projections.
- The projection explains why the runtime is healthy, degraded, or needs
  attention without recomputing policy.
- WebUI Runtime Console shows this state near timeline metrics.
- The gate validates unit tests, WebUI tests, optional live scenarios, no stale
  version text, no dirty service residue, and whitespace correctness.

## Phase 1: Runtime Health Projection

Add `health_summary` to `/api/runtime/timeline`.

Fields:

- `status`: `healthy`, `attention`, or `degraded`
- `score`: 0-100 deterministic quality score
- `event_count`
- `failed_events`
- `degraded_events`
- `open_tasks`
- `positive_agent_lift`
- `latest_policy`
- `latest_value_score`
- `reasons`
- `scope_counts`

Acceptance:

```bash
cargo test -p cowd-cli runtime_timeline_projects_health_summary -- --nocapture
cargo test -p cowd-cli runtime_projection_degrades_missing_sources -- --nocapture
```

## Phase 2: Runtime Console

Show runtime health in the WebUI Runtime Console using the existing timeline
payload. No new polling loop is introduced.

Acceptance:

```bash
cd webui && npm test
```

## Phase 3: v0.8.22 Gate

Run the focused runtime gate and optional live scenarios.

Acceptance:

```bash
scripts/v0822_eval.sh
COWD_V0822_LIVE=1 scripts/v0822_eval.sh
```
