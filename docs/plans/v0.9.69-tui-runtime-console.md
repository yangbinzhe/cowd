# v0.9.69 TUI Runtime Console

## Goal

Move the TUI closer to a daemon runtime console by making session attachment,
replay, lease, and event subscription explicit in the startup path.

## Implemented Scope

- Extended `DaemonControlClient` with:
  - `session.attach`
  - `session.detach`
  - `session.lifecycle`
  - `session.replay`
- Extended `runtime_snapshot` parsing with lifecycle projection data.
- TUI startup now:
  - checks daemon status first,
  - ensures the selected session exists,
  - attaches a TUI lifecycle actor,
  - replays stored session events from cursor `0`,
  - acquires a collaborative writer lease,
  - subscribes to live daemon session events.
- TUI shutdown now releases the lease and detaches the lifecycle actor.
- Strengthened the live TUI daemon attach scenario to assert lifecycle attach
  and replay status are visible in the terminal.

## Non-Goals

- This version does not redesign the full TUI information architecture.
- It does not move every palette command onto the socket queue yet.

## Validation

- Focused control-client tests verify lifecycle socket command payloads and
  runtime snapshot lifecycle parsing.
- Existing TUI daemon attach live scenario now verifies lifecycle attach and
  replay status in a real tmux-driven terminal run.
