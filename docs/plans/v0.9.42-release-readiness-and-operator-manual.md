# v0.9.42 Release Readiness and Operator Manual

## Goal

Close the v0.9.33-v0.9.42 connector runtime batch by making the implemented capabilities understandable, testable, and operable from a clean checkout.

## Completed Capabilities

- Runtime control-plane exposes readiness, degraded/blocked checks, session leases, provider routing, connector summary, task state, and diagnostics.
- Connector runtime declares provider accounts, capabilities, MCP servers, and durable external resource refs.
- ResourceDirectory persists canonical refs through SQLite and supports paging/search.
- Context/evidence bridge injects resource metadata without pulling external bodies into the prompt by default.
- Mock service connector executes through policy, receipt, resource persistence, and audit.
- Feishu read-only connector declares docx/drive/wiki read capabilities, required scopes, account readiness, and canonical resource refs.
- TUI Gateway panel and command palette project connector runtime state.
- WebUI Connector Console projects accounts, capabilities, resources, tools, receipts, and execution results.
- Cross-plane governance applies connector-aware blockers for missing scopes, disabled accounts, unsupported commit, and degraded accounts.
- Connector bulkhead protects service execution with provider-level capacity and cooldown.
- Unified scenario gate validates daemon/API/session lease/connector/audit/resource cleanup.

## Operator Entry Points

- Runtime state: `GET /api/runtime/control-plane`
- Connector summary: `GET /api/connectors/summary`
- Accounts: `GET /api/connectors/accounts`

- WebUI: Runtime Console and Connector Console

## Release Gate

`scripts/release_gate.sh` now includes the v0.9.41 unified scenario and connector/runtime targeted checks. The fast release subset is:

```bash
scripts/v0941_unified_scenario.sh
cargo test -p runtime --lib connector
cargo test -p cowd-cli connector --no-default-features
cargo test -p cowd-cli runtime_control --no-default-features -- --test-threads=1
(cd webui && npm test -- modules.test.js)
(cd webui && PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/snap/bin/chromium npx playwright test connector-console.e2e.spec.js --config=playwright.config.js --browser=chromium)
scripts/tui_smoke.sh
```

## Degraded-state Expectations

Empty or partial config should not crash the daemon.

- Missing memory manager: blocked production readiness with explicit reason.
- Missing provider config: degraded/attention state with provider count `0`.
- Missing Feishu config: disabled/degraded Feishu account, no secret leakage.
- Missing Feishu scopes: connector policy denies before grants can bypass the blocker.
- Missing Playwright managed browser: test can use system Chromium through `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

## Not Included

- Full Feishu document body ingestion into context.
- Feishu write operations.
- Live MCP tool discovery during control-plane inspection.
- Distributed daemon clustering.
- Multi-tenant external secret manager integration.

These are deliberately outside v0.9.42 to keep the connector runtime batch focused on stable contracts, governance, observability, UI projection, and repeatable release checks.

## Residual Risks

- Connector scope names must stay aligned with real provider API permissions as integrations deepen.
- The global tracing capture test remains process-global and should run serially.
- Release gate is broad and may be expensive; use the fast subset during local connector work.
- Feishu read-only operations need a live-account scenario once production credentials are available in CI or a secure local operator environment.

## Acceptance Result

v0.9.42 is considered complete when:

- README and PRODUCT describe the current runtime and connector model.
- Operator checklist exists and matches actual endpoints.
- Release gate includes the unified connector scenario.
- Targeted Rust, WebUI, Playwright, TUI, and unified daemon scenario checks pass.
- No scenario tmux sessions or test listeners remain after validation.
