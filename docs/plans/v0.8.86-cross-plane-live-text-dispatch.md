# v0.8.86 Cross-Plane Live Text Dispatch

## Goal

Close the first real cross-plane execution loop: a permitted commit-mode
`send_text` action can now leave policy/preflight and reach a bound platform
adapter through the shared platform runtime.

## Design

- `PlatformRuntime::dispatch_outbound` sends an outbound message and waits for
  the adapter `send` result through an internal ack command.
- `PlatformRuntime::send_response` keeps the existing enqueue-only behavior for
  legacy asynchronous response paths.
- Runtime shutdown now stores the broadcast shutdown sender so adapter loops do
  not exit immediately after `start()`.
- Cross-plane commit execution maps ready `CrossPlaneOutboundMessagePlan`
  values into `OutboundMessage`.
- Successful live text dispatch records:
  - `status = dispatched`
  - `dispatch_status = sent`
  - `dispatched = true`
  - typed `dispatch_target` in the execution receipt
- Non-text operations still return explicit dispatch blockers until their
  adapters have a verified execution contract.

## TDD Acceptance

- Runtime dispatch waits for adapter send and exposes the sent message in a
  mock adapter.
- Runtime bound adapter lifecycle remains correct after shutdown.
- Cross-plane commit with a ready Feishu text target reaches the mock adapter.
- Cross-plane commit returns a persisted receipt with `dispatch_status = sent`.
- Existing cross-plane dry-run, idempotency, grant, and preflight tests still
  pass.

## Follow-Up

The next step should add provider-level delivery details where adapters expose
message IDs. Image/file dispatch should remain blocked until each platform has a
typed media payload and permission/audit contract.
