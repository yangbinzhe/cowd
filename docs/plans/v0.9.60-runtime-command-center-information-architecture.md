# v0.9.60 Runtime Command Center Information Architecture

## 目标

把 TUI 中承载 daemon/runtime/control-plane 的 GatewayPanel 从线性状态堆叠重组为清晰的运行控制中心，让用户能快速判断系统核心、AI context、任务控制和 connector plane 的状态。

## 实施内容

- 补齐 `RuntimeControlSnapshot.memory_status` 到 `App` 的双向贯通，保证 socket memory 状态能被 TUI 展示。
- `GatewayPanel` 增加 memory status 与全局 degraded reasons 展示。
- 主面板按以下区块呈现：
  - `Core Runtime`：daemon/server、health、uptime、sessions、transport。
  - `AI Context`：runtime readiness、component count、memory status。
  - `Work Control`：tasks、approvals、lease。
  - `Connector Plane`：accounts、capabilities、resources、connector degradation。

## TDD 验收

1. `snapshot_round_trips_memory_status_through_app`：验证 memory status 不再丢失。
2. `render_shows_connector_console_state`：验证 TUI 主工作台展示新的四个核心区块、memory 状态与 degraded reasons。
3. `cargo fmt --check` 与 `git diff --check` 必须通过。

## 评价标准

- TUI 主控制面可以一屏建立运行态心智模型。
- memory/context 能力进入主工作台，不再停留在后台状态。
- 改造不重写 TUI 框架，不引入新的长期复杂度。
