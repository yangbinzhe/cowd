# v0.9.93 IACC Cockpit Report Delivery Bridge

## Goal

`v0.9.93` closes the loop between cockpit report snapshots and the existing
cross-plane governance plane. A generated report is no longer only stored for
human lookup; it can be delivered through the same identity, grant, policy,
audit and execution receipt path used by IACC operational actions.

This version intentionally does not introduce a new notification subsystem.
Report delivery is modeled as a `CrossPlaneAction` so every outbound report has
the same explainability and governance surface as task execution.

## Scope

- Add `POST /api/iacc/cockpit/reports/:id/deliver`.
- Convert an `IaccCockpitReportSnapshot` into a `CrossPlaneAction`.
- Support dry-run and commit mode normalization through the existing IACC bridge
  semantics.
- Persist a delivery receipt on the report snapshot.
- Reuse cross-plane execution receipts for idempotency.
- Keep schema version at `11`; the report table already stores JSON snapshots.

## Runtime Contract

Delivery request:

```json
{
  "mode": "dry_run",
  "idempotency_key": "v0993-report-delivery-cockpit-report-v0993-daily",
  "actor_principal": "user:ops-planner",
  "actor_identity_ref": "iacc://operator/ops-planner",
  "target_ref": "channel://feishu/user/ops-planner"
}
```

Default mapping:

- `actor_principal`: request value, otherwise `report.owner_ref`.
- `requested_capability`: request value, otherwise `channel.feishu.send_text`.
- `source_channel`: request value, otherwise `iacc.report`.
- `session_id`: `report.report_id`.
- `target_ref`: request value, otherwise `report.delivery_ref`.
- `resource_ref`: request value, otherwise `text://{report.title}: {report.summary}`.
- `risk`: `Low`.
- `data_classification`: `Internal`.

Response:

```json
{
  "kind": "iacc.cockpit.report_delivery",
  "mode": "dry_run",
  "status": "planned",
  "dispatch_status": "dry_run",
  "idempotent_replay": false,
  "report": {
    "status": "delivery_planned",
    "delivery_receipts": []
  },
  "cross_plane_execution_receipt": {}
}
```

The real response includes the complete report snapshot and complete
cross-plane receipt.

## Idempotency

When `idempotency_key` is provided, the API first checks the cross-plane
execution ledger. If a receipt already exists, the API re-attaches that receipt
to the report snapshot and returns `idempotent_replay: true`.

The report snapshot deduplicates by `cross_plane_receipt_id`, so repeated
delivery calls do not grow duplicate delivery receipts.

## Acceptance

`scripts/v0993_iacc_cockpit_report_delivery_bridge_scenario.sh` validates:

- gateway and IACC health checks;
- schema version remains `11`;
- health advertises `cockpit_report_delivery_bridge`;
- cross-plane identity and grant can authorize report delivery;
- IACC evidence, quality, analysis and action loop still works;
- cockpit profile and report snapshot generation still works;
- report delivery creates a cross-plane execution receipt;
- report status becomes `delivery_planned`;
- cross-plane execution ledger contains the receipt;
- repeat delivery with the same idempotency key returns the same receipt and
  does not duplicate report delivery receipts.

## Next Version

The next implementation step should move from governed dry-run delivery to
production delivery hardening:

- adapter-specific payload rendering for Feishu, email and webhook targets;
- delivery channel templates and policy constraints;
- scheduled report job runner;
- delivery error classification and retry state;
- cockpit UI projection of delivery status.
