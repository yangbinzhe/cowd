# v0.9.92 IACC Cockpit Report Snapshot

## Goal

Persist generated cockpit reports as immutable snapshots. This closes the first
scheduled-report foundation: a report can be generated from a cockpit profile,
stored with the exact projection used at generation time, and retrieved later
for review or delivery.

This version does not send reports to external channels yet. Delivery remains a
future cross-plane action on top of the persisted snapshot.

## Runtime Contracts

New contracts:

- `IaccCockpitReportRequest`
- `IaccCockpitReportSnapshot`

Report snapshots contain:

- report id;
- profile id;
- owner ref;
- cadence;
- title;
- summary;
- status;
- optional delivery ref;
- optional note;
- embedded cockpit projection;
- created timestamp.

## Store

IACC schema version is now `11`.

New table:

- `iacc_cockpit_report`

New store capabilities:

- `generate_cockpit_report`
- `get_cockpit_report`

Health now reports:

- `cockpit_report_count`

## API

New routes:

```text
POST /api/iacc/cockpit/profiles/:id/reports/generate
GET  /api/iacc/cockpit/reports/:id
```

New health capabilities:

- `cockpit_report_snapshot`
- `scheduled_report_foundation`

## Acceptance

Runtime tests prove:

1. a cockpit report can be generated from a saved profile;
2. the report embeds a projection with cockpit widgets;
3. the report is persisted and retrievable;
4. health counts persisted report snapshots.

Scenario script:

```text
scripts/v0992_iacc_cockpit_report_snapshot_scenario.sh
```

The gateway scenario proves through API:

1. schema version 11 is exposed;
2. report snapshot capabilities are visible;
3. the IACC operational pipeline still produces cockpit projection data;
4. a report can be generated from a cockpit profile;
5. the report can be retrieved by id;
6. health reports `cockpit_report_count: 1`.

## Next Version

`v0.9.93` should add the first delivery bridge from report snapshots to
cross-plane notification actions, still with idempotent receipts and human
review semantics.
