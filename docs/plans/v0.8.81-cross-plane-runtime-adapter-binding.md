# v0.8.81 Cross-Plane Runtime Adapter Binding

## Goal

Replace static cross-plane adapter binding placeholders with a real runtime
snapshot. Cross-plane preflight, execution planning, WebUI, and TUI visibility
must know whether a configured channel adapter is actually bound to a running
adapter loop.

## Design

- Add read-only adapter binding APIs to `PlatformRuntime`.
- Keep API state wiring optional so disabled channel systems and unit tests
  degrade to `adapter_bound=false` instead of failing.
- Attach the daemon-owned `PlatformRuntime` to `AppState` before routes are
  built.
- Resolve binding by platform name and platform type, including hyphen and
  underscore variants.
- Keep commit execution blocked until live dispatch is implemented. A bound
  runtime now reports `dispatch_not_implemented` rather than the misleading
  `adapter_not_bound`.

## Acceptance

- Runtime reports bound adapters after `start()` and clears them after
  `shutdown()`.
- `/api/cross-plane/action/adapters` reports `adapter_bound=true` when the
  platform runtime has a live adapter handle.
- `/api/cross-plane/action/preflight` includes the same runtime binding
  snapshot.
- Commit mode distinguishes missing adapters from bound-but-not-yet-dispatched
  adapters.
- Existing cross-plane no-runtime behavior remains degraded but stable.

## Follow-Up

- Add a dispatch target builder that maps cross-plane actions to
  `SessionKey`/`OutboundMessage`.
- Add live commit execution behind explicit policy, idempotency, and audit
  receipts.
- Surface dispatch target diagnostics in WebUI and TUI before enabling send.
