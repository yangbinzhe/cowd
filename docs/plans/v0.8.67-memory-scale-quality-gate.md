# v0.8.67 Memory Scale Quality Gate

## Objective

Close one concrete product gap: memory must have a repeatable large-candidate retrieval quality gate, not only CRUD and direct-id persistence tests.

## Gap Closed

Previous tests proved entries can be written, read by id, persisted, and bounded in context packets. They did not prove that a large noisy memory set can still return the correct knowledge through normal search.

## Implementation

- Added `memory::eval`.
- Added reusable retrieval evaluation:
  - R@K
  - MRR
  - p50/p95/max latency
  - misses with returned ids
  - pass/fail against thresholds
- Upgraded `longmem_eval_harness`:
  - 100 target facts
  - 400 distractors
  - real FTS search query per fact
  - R@5 threshold
  - p95 latency threshold

## Acceptance

- Retrieval quality is measured through the same `search_memories` path used by runtime/API.
- Direct-id lookup no longer counts as recall quality.
- The gate fails with explicit misses when the correct memory is not returned in top-k.
- The gate fails when p95 search latency exceeds the configured threshold.
- The implementation adds no runtime background dependency and does not affect normal memory operations.

## Verification

- `cargo test -p cowd-memory eval`
- `cargo test -p cowd-memory --test longmem_eval_harness -- --nocapture`
- `cargo test -p cowd-memory --test performance_bench -- --nocapture`
- Full release gate before promotion
