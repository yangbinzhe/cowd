# v0.8.71 Cross-Plane Grant Lifecycle

## Goal

Close the permission lifecycle gap in cross-plane operations. A cross-channel
action must be explainable after the fact: which policy version evaluated it,
which grant matched it, whether that grant was consumed, and what remained.

## Scope

- Add stable decision evidence to cross-plane audit records.
- Consume `single_use` grants on successful matched-grant decisions.
- Exclude exhausted grants from active grant summaries and future decisions.
- Surface recent policy evidence in the WebUI gateway panel.

## Acceptance

- A high-risk action with a single-use grant is allowed once.
- The same action requires approval after the grant is consumed.
- Audit records include policy version, matched grant id, consumed grant id,
  and remaining uses.
- Existing persisted audit records remain loadable through serde defaults.

## Validation

- Runtime unit tests cover grant consumption and audit evidence.
- API tests cover create-grant, simulate twice, and audit inspection.
- WebUI tests cover gateway evidence rendering.
- Release gate must pass before commit.
