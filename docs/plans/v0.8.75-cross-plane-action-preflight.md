# v0.8.75 Cross-Plane Action Preflight

## Goal

Close the gap between policy primitives and real channel execution. Before a
channel or UI attempts a cross-plane operation, it must be able to ask one
side-effect-free question: can this action execute now?

## Scope

- Add side-effect-free cross-plane decision evaluation.
- Add `POST /api/cross-plane/action/preflight`.
- Combine identity resolution, policy decision, and platform readiness.
- Return evaluated action, target platform, platform readiness, executable
  status, and blockers.
- Ensure preflight does not consume single-use grants and does not write audit.

## Acceptance

- Preflight resolves actor identity before policy evaluation.
- Preflight blocks when policy requires approval.
- Preflight blocks when the target platform is missing or degraded.
- Preflight allows only when both policy and target platform are ready.
- A following real policy simulation still consumes a single-use grant exactly
  once.

## Validation

- Runtime unit test proves pure decision does not consume grants or audit.
- API test proves identity + policy + platform readiness preflight.
- WebUI API contract test covers the preflight route.
- Release gate must pass before commit.
