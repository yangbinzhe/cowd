# v0.8.78 Cross-Plane Execution Idempotency

## Goal

Make cross-plane execution safe for retries before live channel dispatch is
enabled. A network retry, UI refresh, or agent retry must not create duplicate
execution records, duplicate audit evidence, or future duplicate channel sends.

## Design

- Persist `CrossPlaneExecutionReceipt` in the cross-plane control snapshot.
- Add `GET /api/cross-plane/action/executions`.
- `POST /api/cross-plane/action/execute` checks `idempotency_key` before
  evaluating a new action.
- A repeated key returns the original receipt with `idempotent_replay=true`.
- New executions record one audit record and one execution receipt.
- Snapshot loading remains backward-compatible through a defaulted executions
  field.

## Acceptance

- Repeating the same execution request with the same key returns the same
  receipt and audit id.
- Execution history lists each receipt once.
- WebUI API exposes execution history.
- Release gate remains green.
