# v0.8.15 Lean Runtime Core Spike

## Goal

Validate a minimal, high-performance runtime core slice without changing provider behavior or widening the orchestration surface.

Focus areas:

- Runtime Trace can point at a compact context probe instead of requiring full prompt replay.
- Context Stable Head can be compared cheaply across turns to estimate prompt-cache reuse.
- Performance degradation can be represented as a deterministic path before larger runtime policy work.

## Experiment Hypotheses

1. Stable head reuse is observable from existing `ContextEnvelope` diagnostics.
   - Dynamic memory, tool trace, task, and workspace changes must not change `stable_head_hash`.
   - A stable head change must be visible as a non-reusable comparison.
2. Context pressure can be summarized without rebuilding or scanning raw prompt content.
   - The probe should use envelope counts, budget tokens, pressure basis points, and existing degraded sources.
   - The probe must not mutate `ContextEnvelope` selection, omission, or assembly.
3. Degradation can start as a small deterministic enum.
   - Low pressure plus missing sources -> `SourceFallback`.
   - Lease omissions or elevated pressure -> `TrimDynamicTail`.
   - High pressure -> `SummarizeEvidence`.
   - Critical pressure -> `HandoffBoundary`.

## Minimal Artifact

Runtime crate additions:

- `ContextLeanProbe`
- `StableHeadComparison`
- `ContextPressureLevel`
- `ContextDegradationPath`
- `ContextRuntimeKernel::lean_probe(...)`
- `ContextRuntimeKernel::compare_stable_head(...)`
- `ContextRuntimeKernel::pressure_level(...)`
- `ContextRuntimeKernel::degradation_path(...)`

These are read-only helpers around existing `ContextEnvelope` data. They avoid new storage, new endpoints, and broad execution rewiring.

## Evaluation Metrics

| Metric | Target |
| --- | --- |
| Stable head reuse check | O(1) over stored hashes |
| Probe construction | O(1) over envelope metadata, plus cloning degraded source list |
| Core behavior change | None; envelope build and prompt assembly unchanged |
| Pressure classification | deterministic thresholds at 70%, 85%, and 90% |
| Degradation visibility | one enum value suitable for RuntimeRun/WebUI/TUI summaries |

## Acceptance

- Stable head comparison reports reusable when only dynamic tail changes.
- Lean probe reports critical pressure as `HandoffBoundary`.
- Lean probe distinguishes degraded source fallback from budget pressure.
- Lease omission appears as the minimum tail-trim degradation path.
- `cargo check -p cowd-cli` passes after the runtime API additions.
