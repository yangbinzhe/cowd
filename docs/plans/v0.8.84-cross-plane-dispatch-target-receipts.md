# v0.8.84 Cross-Plane Dispatch Target Receipts

## Goal

Persist the dispatch target plan into cross-plane execution receipts. Operators
should be able to inspect historical dry-run, blocked, and future commit
attempts with the exact target snapshot that existed at execution time.

## Design

- Add an optional `dispatch_target` field to `CrossPlaneExecutionReceipt`.
- Use `serde(default)` so existing control-state files keep loading.
- Store the API readiness dispatch target as a JSON snapshot when recording an
  execution receipt.
- Let `/api/cross-plane/action/executions` and idempotent replay return the
  persisted target without recomputing it.

## Acceptance

- A dry-run execution with target and payload records a ready dispatch target in
  the receipt.
- Execution listing exposes the same persisted session key.
- Existing policy, audit, idempotency, WebUI, TUI, and release-gate behavior
  remains stable.

## Follow-Up

- Move the dispatch target type into a shared runtime module before live
  dispatch, so API planning and executor code use the same typed contract.
- Implement live commit dispatch with idempotency, audit evidence, and runtime
  send errors reflected in receipts.
