# v0.8.65 Runtime Value Loop Closure

## Objective

Close one concrete product gap: the runtime must expose a single value-loop projection for each session/task timeline so operators can verify whether AI execution actually passed through the required enterprise stages.

This version does not add new agent algorithms, memory stores, or channel protocols. It turns existing runtime events into an auditable closure view.

## Gap Closed

Previous versions implemented the event spine, task kernel, context history, memory pulse, workgraph review, policy projection, and WebUI runtime console. The missing piece was a unified answer to:

- Did this run receive/persist intake evidence?
- Did it build context?
- Did memory participate?
- Was governance/policy/approval recorded?
- Was task lifecycle bound?
- Was execution evidence recorded?
- Did agent/workgraph value get reviewed?
- Are optional channel events visible without blocking local-only runs?

## Implementation

- `/api/runtime/timeline` now returns `value_loop`.
- `value_loop` is computed from the selected session event page and contains:
  - closure status: `complete`, `incomplete`, or `degraded`
  - score
  - required stage coverage
  - missing required stages
  - failed/degraded event counts
  - open task count
  - positive multi-agent lift signal
  - stage-by-stage latest evidence
  - next actions
- WebUI Runtime Console renders the value loop beside runtime health and workgraph summaries.

## Stage Model

Required:

- intake
- context
- memory
- governance
- task
- execution
- agent

Optional:

- channel

Channel is optional because many local coding and analysis runs should still be fully closed without external channel interaction. Channel events are still surfaced when present.

## Acceptance

- A fully observed event sequence reports `complete` and `score = 100`.
- Missing required stages report `incomplete`.
- Failed or degraded events report `degraded`.
- Open task lifecycle records reduce the score and produce next actions.
- WebUI shows the value-loop status, coverage, stages, and first reason/action.
