# v0.9.36 Feishu Read-only Service Connector

## Goal

Add a governed Feishu read-only service plane that can declare capabilities, check account readiness, create canonical resource refs, and persist those refs without performing unsafe writes.

## Delivered

- Added `FeishuReadOnlyServiceConnector`.
- Added low-risk read-only capabilities:
  - `service.feishu.docx.read`
  - `service.feishu.drive.metadata`
  - `service.feishu.drive.download_readonly`
  - `service.feishu.wiki.node_readonly`
- Added service `probe` support to the connector trait.
- Added `/api/connectors/services/feishu.readonly/tools`.
- Added `/api/connectors/services/feishu.readonly/execute`.
- Routed execution through cross-plane receipt/audit semantics.
- Blocked execution when no ready Feishu provider account exists.
- Persisted canonical Feishu resource refs when account readiness and policy allow execution.

## Validation

- `cargo test -p runtime connector`
- `cargo test -p cowd-cli connector`
- `cargo fmt --check`
- `git diff --check`

## Design Notes

- This version does not fetch remote Feishu document bodies into context.
- Existing `DocumentClient` remains the future async read implementation point.
- The service connector establishes the governed service-plane contract first: account readiness, capability, receipt, audit, resource ref, and durable directory.
