# v0.8.83 Cross-Plane Dispatch Target Visibility

## Goal

Expose dispatch target readiness in the operator interfaces. The backend can
now build a safe dispatch plan, so WebUI and TUI must show whether the target is
ready, where the message would go, and why dispatch is blocked.

## Design

- Reuse the existing compact audit-row vocabulary in WebUI.
- Render dispatch targets from execution receipts when available.
- Make the Gateway preflight action show the returned dispatch target instead
  of only a toast.
- Add TUI Gateway dispatch target summaries with status, platform, operation,
  and session/blocker detail.
- Keep the display dense and operational: no large explanation panels, no
  marketing-style layout.

## Acceptance

- WebUI Gateway shows dispatch target status, session key, and payload preview.
- The preflight button produces an inline target readiness preview.
- TUI Gateway renders dispatch target readiness and target session.
- Existing adapter, execution, endpoint, WebUI, and release-gate behavior
  remains stable.

## Follow-Up

- Persist dispatch targets into execution receipts so historical executions can
  always show the exact target snapshot.
- Add a final commit executor once dispatch target, runtime binding,
  idempotency, and audit evidence are all available in one envelope.
