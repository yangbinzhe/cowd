# v0.9.72 Context Runtime

## Target

Make context a first-class runtime object instead of an opaque prompt tail, while keeping the existing provider prompt path stable.

## Implemented

- Added runtime context snapshot types for stable head, runtime header, and dynamic tail.
- Added snapshot diff so dialogue-only changes preserve the stable-head hash and are explicit for cache reuse.
- Added budget explanation per context source, including selected/omitted counts and exhaustion status.
- Added sub-agent context view projection from a parent envelope.
- Added agent view isolation for private peer-agent notes while preserving shared project/workspace facts.
- Extended `/api/context/current` with `snapshot`, `budget_explanation`, and optional `agent_view` via `agent_id`.
- Extended WebUI Context Runtime panel to display runtime snapshot, budget allocations, and child-agent view metrics.
- Added live gateway scenario for the context runtime contract.

## Test Hardening

- `mcp_stdio` reconnect test now accepts both `UnexpectedEof` and `BrokenPipe` as equivalent transport-close evidence.
- Bash execution now prefers `/bin/sh` before PATH lookup so concurrent tests that mutate environment state cannot make shell startup flaky.

## Notes

- Prompt assembly remains in shadow mode: no provider prompt behavior is changed by this version.
- The stable head remains the cache anchor; dynamic and agent views are explicit projections layered below it.
