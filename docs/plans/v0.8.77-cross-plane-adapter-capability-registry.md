# v0.8.77 Cross-Plane Adapter Capability Registry

## Goal

Make cross-plane execution explainable before live channel dispatch exists.
Policy, platform readiness, and adapter capability are separate facts:

- policy answers whether the actor may perform the action;
- platform readiness answers whether configuration exists;
- adapter capability answers whether cowd has a live-capable handler for the
  requested operation;
- adapter binding answers whether a running runtime instance is currently
  available for dispatch.

## Design

- Add `GET /api/cross-plane/action/adapters`.
- Add `adapter_capability` to preflight and execution responses.
- Keep `adapter_bound=false` until execution is wired to a live
  `PlatformRuntime` handle.
- Keep commit mode blocked when a live-capable adapter is not bound.
- Return `dispatch_status=capability_not_supported` for unsupported operations
  instead of conflating that with missing binding.

## Acceptance

- Feishu `send_text`, `send_image`, and `send_file` appear as live-supported
  operations when the platform is configured.
- WeChat iLink `send_text` and `send_image` appear as live-supported operations.
- WeCom `send_text` is live-supported; unsupported operations remain explicit.
- WebUI API exposes the registry.
- Existing preflight and execution behavior remains stable.
