# v0.8.87 Cross-Plane Dispatch Outcome Audit

## Goal

Make live cross-plane execution auditable beyond coarse status strings. Each
execution receipt can now include a typed dispatch outcome that records what was
attempted and whether adapter delivery succeeded.

## Design

- `CrossPlaneDispatchOutcome` records:
  - attempt time
  - platform
  - operation
  - session key
  - status
  - error
  - provider message id placeholder
- `CrossPlaneExecutionReceipt.dispatch_outcome` is optional and defaults during
  deserialization, preserving old receipt files.
- Cross-plane commit writes `sent` outcomes on successful text dispatch.
- Cross-plane commit writes `failed` outcomes when adapter send returns an
  error.
- WebUI gateway execution history renders dispatch outcome summaries under each
  receipt.

## TDD Acceptance

- Runtime receipt serde round-trips typed dispatch target and outcome.
- API commit returns `dispatch_outcome.status = sent` for successful mock live
  dispatch.
- Execution receipt persists outcome session details.
- WebUI module tests render Dispatch Outcome.

## Follow-Up

Adapters should later return provider message IDs through a typed send result.
That can populate `provider_message_id` without changing the receipt shape.
