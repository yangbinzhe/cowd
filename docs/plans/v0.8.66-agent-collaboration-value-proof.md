# v0.8.66 Agent Collaboration Value Proof

## Objective

Close one concrete product gap: multi-agent collaboration must not only run, it must prove whether it produced enough value to continue using multi-agent mode.

## Gap Closed

Before this version, workgraph and collaboration scorecard data existed, but the operator had to interpret raw numbers manually. This allowed the same planning item to repeat as "multi-agent 1+1>2 is not proven".

## Implementation

- `/api/runtime/timeline` now returns `agent_value`.
- `agent_value` combines:
  - latest `agent.workgraph.reviewed` or planned event
  - `CollaborationScorecard`
  - `value_verdict`
  - active runtime agent policy
- The projection produces:
  - status: `proven`, `review_required`, `insufficient`, `unproven`, `degraded`, or `disabled`
  - recommendation: continue, review conflicts, collect evidence, repair evidence, or prefer single-agent/review-only mode
  - policy threshold and policy pass/fail
  - latest collaboration evidence and reasons
- WebUI Runtime Console renders the decision in an Agent Value card.

## Policy

Multi-agent value is only proven when:

- agent policy is enabled
- value score meets `min_collaboration_score`
- positive lift is present when required
- latest workgraph evidence is not failed/degraded
- conflict review is not pending

If conflict review is required and conflicts exist, the result is `review_required`, not `proven`.

## Acceptance

- Strong positive lift above policy threshold reports `proven`.
- Low score or missing lift reports `insufficient`.
- Unresolved conflicts report `review_required`.
- Missing workgraph evidence reports `unproven`.
- Missing session store reports `degraded`.
- WebUI exposes status, recommendation, threshold, score, lift, conflict count, and reasons.
