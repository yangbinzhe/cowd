# v0.9.82 Validation Framework Unification

## Goal

Make testing fast enough for daily work while keeping release confidence. The
test system must have one source of truth, clear lanes, measured reports, and no
accidental duplication between live and release scenarios.

## Current Facts

- Rust test markers: 3390.
- WebUI tests: 80.
- Largest compile pressure comes from `cowd-cli`, `runtime`, and `cowd-memory`.
- `cowd-cli` test binaries are around 400 MiB in debug builds.
- Existing live/release gates repeat daemon, TUI, WebUI, memory, and channel
  checks.

## New Lanes

| Lane | Command | Purpose |
| --- | --- | --- |
| unit-fast | `scripts/validate.sh unit-fast` | edit feedback: formatting, light crates, targeted heavy probes, WebUI unit |
| contract | `scripts/validate.sh contract` | package and API contracts without browser/tmux scenarios |
| scenario | `scripts/validate.sh scenario` | one debug build plus daemon/TUI/WebUI runtime scenarios |
| release | `scripts/validate.sh release` | clean build, install, setup smoke, and minimal release smoke |
| all | `scripts/validate.sh all` | contract plus scenario |

## Implementation Rules

- `scripts/validate.sh` is the only real runner.
- Existing `validate_fast/core/full/live`, `validate_segmented`, and
  `release_gate` remain compatibility wrappers only.
- Scenario lane builds once and exports `COWD_BIN`; scenario scripts must not
  rebuild unless explicitly requested.
- Release lane does not rerun the entire live suite. It checks installability,
  setup readiness, gateway/WebUI health, TUI attach, and channel permissions.
- Historical eval scripts are archived under
  `scripts/archive/legacy-validation`.

## Acceptance

- `scripts/validate.sh unit-fast` exits 0 and produces a report.
- `scripts/validate.sh scenario` exits 0 and reuses one binary.
- `scripts/validate.sh release` exits 0 and installs `~/AI/cowd-debug-current`.
- Compatibility wrappers still work.
- Archived legacy scripts are not called by active gates.
