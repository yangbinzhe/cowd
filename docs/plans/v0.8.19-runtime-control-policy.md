# Cowd v0.8.19 Runtime Control Policy Plan

v0.8.19 builds on the v0.8.18 runtime closed loop. The goal is to make runtime
decisions configurable, explainable, and visible without adding a heavy
scheduler.

## Goals

- Add a small `RuntimeControlPolicy` control plane.
- Add deterministic `TaskComplexityProfile` scoring.
- Use complexity output to decide when collaboration should run.
- Preserve existing default collaboration behavior.
- Project policy decisions through RuntimeEvent, WebUI, and TUI in later
  phases.

## Phase 1: Policy DTO And Complexity Profile

- Add `runtime_control` module.
- Define:
  - `RuntimeControlPolicy`
  - `TaskComplexityProfile`
  - `TaskComplexityInput`
  - `ComplexityLevel`
  - `AgentMode`
- Keep defaults compatible with v0.8.18 collaboration triggers.

Acceptance:

```bash
cargo test -p runtime runtime_control -- --nocapture
cargo test -p runtime collaboration_turn_records_takeable_closed_loop_result -- --nocapture
```

## Phase 2: Conversation Runtime Integration

- Replace hard-coded collaboration trigger with policy evaluation.
- Keep `infer_required_skills` unchanged for this phase.
- Degrade to default policy if config is missing.

Acceptance:

```bash
cargo test -p runtime agent_collaboration -- --nocapture
cargo test -p cowd-cli runtime_ -- --nocapture
```

## Phase 3: Effective Config Projection

- Expose read-only effective runtime control policy through API.
- Include source/default metadata and warnings.

Acceptance:

```bash
cargo test -p cowd-cli config -- --nocapture
```

## Phase 4: RuntimeEvent Policy Decisions

- Emit `runtime.policy.decided`.
- Include complexity score, signals, recommended profile, agent mode, and
  review requirement.

Acceptance:

```bash
cargo test -p cowd-memory runtime_event -- --nocapture
cargo test -p cowd-cli runtime_ -- --nocapture
```

## Phase 5: UI Projection

- WebUI Runtime Console shows policy summary.
- TUI Runtime Activity shows complexity level and agent mode.

Acceptance:

```bash
cd webui && npm test
cargo test -p cowd-cli runtime_ -- --nocapture
```

## Phase 6: v0.8.19 Gate

- Add `scripts/v0819_eval.sh`.
- Include the existing v0.8.18 closed-loop gate plus `runtime_control`.

Acceptance:

