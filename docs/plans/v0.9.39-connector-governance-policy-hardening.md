# v0.9.39 Connector Governance Policy Hardening

Goal: route connector service, MCP, and channel actions through one cross-plane governance explanation.

Delivered:

- Added connector-aware policy context and audit evidence:
  - provider
  - plane
  - capability
  - provider account
  - account status/reason
  - resource ref
  - required/missing scopes
  - requested mode
- Cross-plane simulate/preflight/execute now evaluate connector context from the registry snapshot.
- Service connector execution now uses connector-aware decision/audit.
- Feishu read-only capabilities declare explicit read scopes.
- ProviderAccount scopes are projected from gateway platform configuration.
- Mock docs is registered in connector snapshot as a ready local service connector.

Policy order:

1. Connector hard blockers: missing scope, disabled account, degraded commit, unsupported commit.
2. Matching grant.
3. Identity trust.
4. Data classification.
5. Connector explicit approval flag.
6. Risk policy.

Validation:

- `cargo test -p runtime cross_plane_policy`
- `cargo test -p runtime connector`
- `cargo test -p cowd-cli connector --no-default-features`
- `cargo test -p cowd-cli cross_plane --no-default-features`
- `cargo fmt --check`
- `git diff --check`

Design notes:

- Connector context is a plain policy input, not a connector SDK dependency.
- Grants cannot bypass missing account scopes or disabled accounts.
- Existing channel dispatch remains unchanged; connector evidence only enriches governance decisions.
