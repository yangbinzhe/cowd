# Cowd v0.8.17 Runtime Event Kernel Plan

## Version Goal

v0.8.17 upgrades Cowd from a feature-composed agent app into an event-driven AI
runtime kernel. The target architecture is:

```text
RuntimeCommand
  -> RuntimeEventLog
  -> RuntimeProjection
  -> AgentWorkGraph
  -> MemoryPulseConsumer
  -> ContextPolicyEngine
  -> TUI/WebUI Runtime Cockpit
```

The purpose is not to add a broad new subsystem. The purpose is to make the
existing session, agent, task, tool, memory, context, policy, and UI capabilities
share one durable, replayable, inspectable runtime spine.

## Current Reality

Strong foundations already exist:

- `SessionKernel` wraps active runtimes, `UnifiedSessionStore`, and event bus.
- `UnifiedSessionStore` provides SQLite-backed session records, messages, and
  events.
- `ContextRuntimeKernel` provides typed envelopes, lean probes, and policy
  decisions.
- `CollaborationBoard` provides multi-agent scorecards and review packets.
- `MaintenanceQueue` persists reviewable memory maintenance candidates.
- WebUI/TUI can already display context/runtime/memory signals.

Remaining architectural gaps:

- `SessionKernel` is still mostly an accessor instead of a command/event
  lifecycle boundary.
- Runtime events are still payload conventions rather than a first-class event
  schema.
- Agent collaboration has DTOs and tests, but not a persistent work graph.
- Memory maintenance is durable, but memory self-organization is not yet an
  event consumer.
- Context policy is visible, but does not yet produce auditable proposals and
  safe local actions.
- WebUI/TUI still consume scattered endpoint shapes rather than unified
  projections.
- JSONL remains present in legacy runtime/session paths and must be isolated
  from the runtime session source of truth.

## Design Principles

1. Event log is the runtime source of truth.
2. Commands validate intent; events record fact.
3. Projections are disposable and rebuildable.
4. Hot paths stay bounded; expensive organization is asynchronous.
5. Memory evolves through auditable events, not hidden rewrites.
6. Context policy may propose or apply only safe, explicit actions.
7. UI consumes projections, not internal backend module shapes.
8. JSONL is an import/export/debug codec, not runtime storage.

## Phases

### Phase 0: Version And Documentation Consistency

Update workspace version, README, and plan references so product metadata
matches the v0.8.17 target.

### Phase 1: RuntimeEventLog

Introduce first-class `RuntimeEvent`, `RuntimeRef`, event scopes, and paged
querying. Existing session events may act as the storage bridge initially.

### Phase 2: RuntimeCommand And SessionLifecycleKernel

Route session lifecycle through commands and event emission:
create, activate, append message, run turn, pause, resume, fork, archive, delete.

### Phase 3: DB-first And JSONL Isolation

Remove JSONL from the runtime session main path. Keep explicit import/export and
debug bundle codecs.

### Phase 4: AgentWorkGraph

Represent multi-agent work as persistent graph nodes and edges linked to runtime
spans, collaboration boards, and memory candidates.

### Phase 5: MemoryPulseConsumer

Subscribe memory maintenance and consolidation to runtime events. Emit auditable
memory pulse events without blocking the main turn.

### Phase 6: ContextPolicyEngine

Upgrade context policy decisions into proposals/actions with safety boundaries,
expected token savings, affected sources, and audit events.

### Phase 7: Runtime Projection API

Expose stable projections for runtime snapshot, timeline, workgraphs, memory
pulse, and context policy.

### Phase 8: Runtime Cockpit UI

Make TUI/WebUI consume projection APIs and provide drilldown from session to
context, agent, memory, and policy.

### Phase 9: Complexity Reduction

Split `api_routes.rs` and `conversation.rs` along the new runtime kernel
boundaries, without mixing behavior changes into mechanical moves.

### Phase 10: v0.8.17 Gate

Add `scripts/v0817_eval.sh` covering unit, API, WebUI, optional live browser,
optional tmux, large-state, and cleanup checks.

## Completion Criteria

v0.8.17 is complete when:

- Runtime events are the shared fact model.
- Session lifecycle emits command-derived events.
- Agent work can be persisted, queried, and traced through parent sessions.
- Memory pulse consumes events and degrades locally on failure.
- Context policy proposals are visible, auditable, and safely actionable.
- WebUI/TUI use projections for the runtime cockpit.
- JSONL no longer participates in runtime session storage.
- v0.8.17 default and live gates pass.
