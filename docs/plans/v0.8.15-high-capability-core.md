# v0.8.15 High-Capability Core Spike

## Spike Goal

Validate two high-capability bets with a small, executable slice:

- Multi-agent work can produce measurable lift over a single strongest agent when agents return complementary decisions, evidence, next actions, or memory updates.
- Memory Pulse can make shared memory feel alive by surfacing explicit remember, refresh, promote, and retire candidates without turning every run into a heavy maintenance workflow.

This spike stays intentionally light. It should improve observability of existing agent collaboration before adding new orchestration, storage, UI, or background services.

## Experiment Hypotheses

1. **1+1 > 2 can be detected locally.** If two or more sub-agents contribute distinct structured signals, the runtime can compute a deterministic synthesis lift above the strongest single-agent contribution.
2. **Conflict surfacing is valuable before consensus.** Agent-reported conflicts, risks, blocked states, and abnormal completion should be visible in the synthesis before any leader finalizes a decision.
3. **Memory Pulse should be candidate-first.** Live-memory updates should begin as reviewable candidates extracted from agent output, not as automatic writes or deletes.
4. **The first slice should be test-only and service-free.** A useful baseline can run inside normal Rust checks without providers, ports, tmux, or long-lived workers.

## Implemented Slice

Runtime now builds a lightweight `CollaborationBoard` from `SubAgentResult` values:

- `SharedBoardEntry` extracts decisions, evidence, surfaced conflicts, memory pulse candidates, and next actions from structured output prefixes.
- `CollaborationScorecard` computes completion rate, synthesis lift, complementarity, active-memory score, conflict count, and pulse count.
- `CollaborationOrchestrator::synthesize` includes a shared-board scorecard and memory pulse section in the human-readable synthesis.

Recognized Memory Pulse prefixes:

- `Memory:` / `Remember:` -> remember candidate.
- `Refresh:` / `Stale:` -> refresh candidate.
- `Promote:` -> authority promotion candidate.
- `Forget:` / `Retire:` -> retirement candidate.

Recognized conflict prefixes:

- `Conflict:`
- `Risk:`
- `Blocked:`
- `Disagreement:`

## Evaluation Metrics

| Metric | Target for Spike | Why It Matters |
| --- | --- | --- |
| Completion rate | Reported for every synthesis | Separates collaboration quality from failed execution. |
| Synthesis lift | `> 1.0x` for complementary agents | Gives a concrete signal for the 1+1>2 hypothesis. |
| Complementarity score | `> 0.0` when agents add non-duplicate signals | Distinguishes diversity from repeated agreement. |
| Surfaced conflicts | Nonzero when agents report conflict/risk/blocked states | Keeps disagreement visible before synthesis. |
| Memory pulse count | Nonzero when agents propose remember/refresh/promote/retire | Makes live memory reviewable without automatic mutation. |
| Active-memory score | Fraction of agents that produced pulse candidates | Shows whether memory is participating in the run. |

## Local Acceptance

- Unit tests cover board extraction, multi-agent lift scoring, conflict surfacing, and synthesis output.
- `cargo test -p runtime agent_collaboration` passes.
- `cargo check -p cowd-cli` passes or reports only pre-existing unrelated issues.

## Non-Goals

- No new agent scheduler.
- No background memory daemon.
- No automatic memory mutation from pulse candidates.
- No UI panel or API endpoint until the scoring contract proves useful.
