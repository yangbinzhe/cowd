# v0.8.12 Memory Kernel Refactor

## Design Correction

The memory architecture must stay pure.

The target is not a stack of RAG, vector search, graph databases, wiki pages, snapshots, and agent notes.

The target is one coherent memory organism:

```text
Experience -> Trace -> Pattern -> Orientation -> Action -> Revision
```

Five memory layers remain valuable, but they are a governance structure. Trace / Pattern / Orientation is the runtime organization model.

This means:

- L0-L4 define authority, scope, and write rules.
- Trace/Pattern/Orientation defines how knowledge moves through the organism.
- Session and agent integration must go through one MemoryKernel, not direct ad-hoc calls.

## Core Principle

Cowd memory should not become smarter by keeping more active content.

It should become smarter by maintaining the shortest reliable path from current intent to valid orientation.

Large-scale memory is achieved by:

- preserving traces.
- organizing patterns.
- keeping orientation small and authoritative.
- making all cold knowledge reachable through paths.
- never deleting history just because it is no longer active.

## Five-Layer Governance Model

### L0: Constitution

Purpose:

- identity, system doctrine, protected constraints, human-defined or AI-established foundational rules.

Authority:

- user/system highest authority.
- AI may propose L0 changes, but cannot silently mutate protected L0.

Runtime role:

- Orientation.

Implementation:

- existing `MemoryLayer::L0`.
- write source limited by `MemoryWriteGuard`.
- explicit audit required for mutation.

Best mechanisms:

- deterministic storage.
- explicit versioning.
- no vector-only recall.
- direct pinning into context when enabled.

### L1: Core Instinct

Purpose:

- stable working preferences, default behavior, durable habits, model/session operating assumptions.

Authority:

- user explicit > repeated confirmed behavior > AI inference.

Runtime role:

- Orientation plus high-confidence Pattern.

Implementation:

- existing `MemoryLayer::L1`.
- short TTL cache is valid, but entries must still carry source and state.

Best mechanisms:

- preference extraction.
- reinforcement scoring.
- bounded active cache.
- user correction supersession.

### L2: Project Mind

Purpose:

- project conventions, architecture, code symbols, tests, current requirements, project-specific decisions.

Authority:

- repository facts and tests > project decisions > tool observations > assistant inference.

Runtime role:

- Pattern and Orientation.

Implementation:

- existing `MemoryLayer::L2`.
- `ProjectScopeManager`, code indexer, symbol-memory links, project KG.

Best mechanisms:

- FTS for exact symbols/errors.
- code symbol graph.
- project KG.
- incremental file fingerprinting.
- decision lineage.

### L3: Deep Memory

Purpose:

- long-term knowledge, document insights, compressed sessions, historical observations, low-frequency but reusable knowledge.

Authority:

- evidence-backed active claims can be promoted; stale or superseded claims remain historical.

Runtime role:

- Trace and Pattern.

Implementation:

- existing `MemoryLayer::L3`.
- verbatim evidence and compressed summaries.

Best mechanisms:

- hybrid FTS/vector retrieval.
- temporal state.
- cluster distillation.
- cold archive with path recall.

### L4: Shared Collective

Purpose:

- team memory, cross-agent decisions, delegation results, peer observations, shared project context.

Authority:

- consensus and role reputation matter, but cannot override L0 or verified project facts.

Runtime role:

- Pattern and shared Orientation.

Implementation:

- existing `MemoryLayer::L4`.
- `SharedLayer`, L4 event bus, agent directory, reputation, memory sync.

Best mechanisms:

- scope/visibility fence.
- event-driven peer updates.
- consensus/conflict records.
- parent_session_id and task lineage.

## Runtime Organization Model

### Trace

Raw or near-raw experience:

- session messages.
- tool outputs.
- documents.
- file observations.
- agent transcripts.

Trace is high volume and mostly cold. It is preserved for evidence and reconstruction.

### Pattern

Structured meaning extracted from traces:

- decisions.
- preferences.
- entity facts.
- recurring errors.
- code relationships.
- document topic clusters.

Pattern is the navigational fabric of memory.

### Orientation

Current effective knowledge:

- active L0/L1.
- current project doctrine.
- accepted architecture.
- active task state.
- relevant team decisions.

Orientation is small, authoritative, and directly injected into session/agent context.

## Minimal Core Data Model

Do not introduce many conceptual stores. Normalize around five concepts.

### Atom

The one interpreted memory unit.

Maps to current `MemoryEntry`.

Required fields:

- id.
- layer.
- scope.
- source.
- content/title.
- confidence.
- salience.
- state.
- validity.
- source_agent.
- session_id.
- evidence pointer.

### Evidence

Immutable source material.

Maps to current `VerbatimSink`, blob store, session events, tool sandbox, and imported documents.

### Link

Typed relationship.

Unifies:

- `MemoryEntry.relations`.
- KG triples.
- symbol-memory links.
- session links.
- agent links.
- supersedes/contradicts/supports.

### State

Temporal lifecycle state:

- candidate.
- active.
- conflicted.
- superseded.
- stale.
- archived.

### Recall

Audit record:

- query/intent.
- selected atoms.
- omitted atoms.
- reasons.
- evidence pointers.
- conflicts.
- budget.

## Lifecycle

Every session/agent turn must pass through the same loop:

```text
Bind -> Prepare -> Observe -> Relate -> Judge -> Distill -> Activate/Archive -> Explain
```

### Bind

Bind:

- session_id.
- project_id.
- agent_id.
- team_id.
- task_id.
- model/context budget.

### Prepare

Build a `MemoryContextPacket`:

- orientation.
- supporting patterns.
- warnings.
- conflicts.
- evidence pointers.
- dropped/omitted reasons.

### Observe

Capture session messages, tool outputs, and agent results as trace/evidence.

### Relate

Attach links:

- entity.
- symbol.
- session.
- agent.
- project.
- decision lineage.
- contradiction/supersession.

### Judge

Apply:

- authority.
- confidence.
- recency.
- repetition.
- scope.
- user correction.
- code/test verification.

### Distill

Convert repeated traces into patterns and stable patterns into orientation.

### Activate/Archive

Keep current orientation bounded. Archive does not delete.

### Explain

Every injected memory must be able to answer:

- why this?
- why now?
- from what evidence?
- why not the older version?

### Critical Integration Gaps

1. No MemoryKernel boundary.
   Runtime, sub-agents, JPS, API, and TUI call `CognitiveContextManager` directly.

2. Session/project binding is incomplete.
   Runtime sets `active_agent=primary` but does not uniformly bind session/project/task before every memory lifecycle operation.

3. L0/L1 governance is not yet productized.
   WriteGuard exists, but protected mutation, audit, proposal, and user approval paths are not unified.

4. Relations are fragmented.
   `relations_json`, KG triples, symbol links, and session/agent links are not one path API.

5. State is implicit.
   Confidence/staleness exist, but candidate/active/superseded/conflicted/archived is not a first-class lifecycle.

6. Recall is still mostly retrieval.
   It should become path-based orientation selection with explanation.

7. Large-scale memory needs cold reachability.
   `VerbatimSink`, ToolSandbox, vector, FTS, and KG exist, but there is no single cold-to-active promotion policy.

## Best Implementation Choices

### Exact And Structured Recall

Use:

- SQLite FTS5.
- symbol index.
- scope filters.
- temporal state filters.

Reason:

- exact identifiers, errors, code names, and decisions must not depend on embeddings.

### Semantic Recall

Use:

- external embedding configuration already present in `VectorConfig`.
- vector search only as candidate generation.
- re-rank with FTS, scope, authority, recency, and relation distance.

Reason:

- embeddings are useful but not authoritative.

### Path Recall

Use:

- existing KG/symbol links/relations first.
- add a unified link table/interface.
- bounded BFS or Dijkstra-like scoring by relation type, distance, salience, and authority.

Reason:

- memory recall is path finding, not chunk similarity.

### Distillation

Use:

- deterministic heuristics for first pass.
- optional configured LLM summarizer for cluster naming and summary.
- preserve evidence pointer.

Reason:

- model capability helps interpretation, but source of truth must stay inspectable.

### Conflict And Authority

Use:

- extend existing `FactChecker` and `ConflictResolver`.
- add general claim keys beyond toy triples.
- authority scoring:
  - L0/user explicit.
  - code/test/tool verified.
  - project decision.
  - multi-agent consensus.
  - assistant inference.
  - compressed/imported low-confidence.

Reason:

- current active knowledge must be clean; old knowledge remains recoverable.

### Large Scale

Use:

- hot orientation cache.
- warm FTS/vector/link indexes.
- cold evidence/verbatim/blob.
- background distillation.
- bounded prepare_context budget.

Reason:

- all information can be findable without all information being active.

## Implementation Rules

1. Do not replace existing memory modules at once.
   Wrap, normalize, and migrate gradually.

2. Do not make embedding mandatory.
   External embedding config remains optional; FTS/link/path recall must work alone.

3. Do not treat graph/vector/wiki as independent product concepts.
   They are indexes/views over atoms.

4. Do not delete forgotten memory by default.
   Archive or supersede.

5. Do not allow memory errors to crash session/agent execution.
   Report degraded memory state.

6. Do not let sub-agents bypass governance.
   All agent memory writes go through MemoryKernel.

## Final Shape

The final memory system should feel simple:

```text
L0-L4 decide who may know, write, and override.
Trace/Pattern/Orientation decide how knowledge lives.
MemoryKernel decides how every session and agent uses it.
Links decide how cold knowledge becomes reachable.
State decides what is active, historical, superseded, or archived.
Recall decides the shortest reliable path to current valid orientation.
```

That is the pure architecture.

It uses the strengths already present in Cowd, but removes accidental complexity by giving every part one role.
