# v0.8.88 Platform Send Result Contract

## Goal

Promote platform delivery from a boolean success path to a typed result contract
so cross-plane execution receipts can retain provider delivery identifiers.

## Design

- `PlatformAdapter::send` now returns `SendResult`.
- `PlatformRuntime::dispatch_outbound` returns the adapter `SendResult` through
  its synchronous ack path.
- Platforms that do not expose a message id return `SendResult::success(None)`.
- Feishu text dispatch extracts `data.message_id` from normal and fallback send
  responses when available.
- Cross-plane live text execution writes `provider_message_id` into
  `CrossPlaneDispatchOutcome`.
- Existing async enqueue paths still ignore the result after logging adapter
  failures.

## TDD Acceptance

- Runtime dispatch waits for adapter send and returns the mock message id.
- Cross-plane commit stores provider message id in API response and receipt
  outcome.
- Feishu live/manual tests compile against `SendResult`.

## Follow-Up

Next platform-specific work should expose message ids for media/card/file
dispatch and normalize retryable delivery errors for operator-visible retry.
