# v0.9.84 IACC Entity Relation Network

## Goal

Turn IACC from a metric/event-only closed loop into a structured business object
network. This version adds canonical entities, source-key resolution, typed
relations, and bounded impact tracing so later manufacturing, metric-dependency,
attribution, and cockpit work can reason across ERP/MES/PLM/SRM/WMS boundaries.

## Baseline

The latest merged baseline is `v0.9.83`:

- `v0.9.82` unified validation lanes.
- `v0.9.83` merged the IACC runtime into master/develop.
- The next IACC business capability version therefore starts at `v0.9.84`.

## Runtime Contracts

New IACC contracts:

- `IaccEntity`
- `IaccEntityInput`
- `IaccSourceKey`
- `IaccRelation`
- `IaccRelationInput`
- `IaccImpactHop`
- `IaccImpactTrace`

The new graph layer keeps IACC at the operating semantic layer:

```text
source system keys
  -> canonical entity
  -> relation network
  -> bounded impact trace
  -> later metric dependency / attribution / cockpit surfaces
```

## Store

Schema version is now `6`.

New tables:

- `iacc_entity`
- `iacc_entity_source_key`
- `iacc_relation`

New store capabilities:

- `upsert_entity`
- `get_entity`
- `resolve_entity_by_source_key`
- `list_entities`
- `upsert_relation`
- `list_entity_relations`
- `impact_trace`

## API

New routes:

- `GET /api/iacc/entities`
- `POST /api/iacc/entities/upsert`
- `POST /api/iacc/entities/resolve-source-key`
- `GET /api/iacc/entities/:id`
- `GET /api/iacc/entities/:id/relations`
- `GET /api/iacc/entities/:id/impact-path`
- `POST /api/iacc/relations/upsert`

`GET /api/iacc/health` now returns:

- `entity_count`
- `relation_count`

New health capabilities:

- `entity_relation_network`
- `entity_source_key_resolution`
- `entity_impact_trace`

## Acceptance

Runtime tests prove:

- two source-system keys can resolve to one canonical component entity;
- component/product/customer-order relations can be persisted;
- a component impact trace can traverse inbound BOM and order relations.

Scenario script:

```text
scripts/v0984_iacc_entity_relation_scenario.sh
```

The scenario proves via gateway API:

1. schema version 6 is exposed;
2. entity relation capabilities are visible;
3. ERP and PLM source keys merge into one canonical component;
4. product/component/customer-order relations are persisted;
5. an impact path from component reaches the customer order.
