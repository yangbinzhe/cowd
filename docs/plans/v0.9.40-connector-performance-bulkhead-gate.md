# v0.9.40 Connector Performance and Bulkhead Gate

Goal: keep connector growth from slowing or destabilizing the daemon control plane.

Delivered:

- Added `ConnectorBulkhead` runtime primitive:
  - per-provider in-flight cap
  - repeated failure cooldown
  - guard-based release on drop
- Registered the service bulkhead in connector service execution.
- Commit execution is gated per provider; dry-run remains cheap and does not occupy service slots.
- Added stable bulkhead blockers for receipts:
  - `connector.bulkhead:<provider>:busy:<in_flight>/<max>`
  - `connector.bulkhead:<provider>:cooling_down`
- Added base connector capability cache for static capabilities.
- Clamped connector resource pages to a fixed budget:
  - default: 100
  - max: 200

Validation:

- `cargo test -p runtime connector`
- `cargo test -p cowd-cli connector --no-default-features`
- `cargo fmt --check`
- `git diff --check`

Design notes:

- Bulkhead is a small runtime primitive, not an async scheduler.
- Existing channel dispatch remains unchanged.
- Timeouts for live external SDK calls should be layered on concrete async connectors as they move beyond local/read-only mock behavior.
