# v0.8.14 Runtime Orchestration And Product Hardening

## Version Goal

v0.8.14 turns the v0.8.13 context foundation into an auditable AI runtime.

Target loop:

```text
Goal -> RuntimeRun -> ContextEnvelope -> Agent/Tool Execution
     -> Evidence Trace -> Session/Memory/Task Update
     -> Review/Reconcile -> Next Action
```

The version must make Cowd easier to operate on long-running enterprise work:

- every user/API/yolo/agent turn has a run trace.
- every context item can be traced to evidence.
- profile policies control execution, not only diagnostics.
- memory maintenance becomes an explicit background lifecycle.
- WebUI/TUI explain runtime state without reading logs.
- large sessions, workspaces, and memory stores degrade predictably.

## Current Code Reality

Already available:

- DB-first session events and paged event queries.
- persisted `ContextEnvelope` events and historical envelope lookup.
- `ContextRuntimeKernel` with typed envelope, profile leases, omissions, and segment hashes.
- short-term `ToolTrace`, `Workspace`, `Resume`, and `AgentPeer` context packets.
- WebUI/TUI Context views with pressure, recommendations, refs, and historical envelope drilldown.
- explicit JSONL import only; JSONL is not an active context source.

Main gaps:

- no first-class `RuntimeRun` / execution span object.
- `/solo`, `--yolo`, review, resume, and sub-agent profiles are not fully wired into execution lifecycle.
- evidence refs stop at envelope-level inspection; exact payload drilldown is incomplete.
- memory maintenance candidates and review queue are not a durable workflow.
- WebUI is still panel-based, not a unified runtime console.
- TUI has context diagnostics but lacks run timeline and ref navigation.
- performance and failure injection are not yet systematic.

## Phase 1: RuntimeRun Trace Foundation

### Objective

Introduce a durable run trace without changing provider behavior.

### Work

- Add `RuntimeRunStarted` and `RuntimeRunCompleted` session events.
- Add `GET /api/sessions/:id/runs`.
- Include:
  - run id
  - parent run id
  - profile
  - status
  - user intent preview
  - context envelope id when available
  - started/completed timestamps
  - iterations/error
- WebUI API wrapper for run timeline.

### Tests

- API `send_message` records started/completed run events.
- failed turn records failed run event.
- run query returns only runtime run events.
- run event is nonfatal if session store is unavailable.

### Acceptance

- A user/API turn can be audited as a `RuntimeRun`.
- Context envelopes can be associated with the latest run.
- Existing turn behavior is unchanged.

### Parallelizable

- Backend event/API work.
- WebUI API wrapper/tests.
- Documentation and acceptance ledger.

## Phase 2: Profile Policy Execution Binding

### Objective

Make profile policy active in real execution paths.

### Work

- Bind `/solo` to `SoloGoal`.
- Bind `--yolo` and yolo task continuation to `YoloGoal`.
- Bind review commands/stages to `Review`.
- Bind resume startup to `Resume`.
- Bind sub-agent runtime construction to `SubAgent`.
- Add runtime identity/profile setter or scoped profile lease injection.

### Tests

- same task produces different leases for Main vs Yolo vs Review.
- yolo preserves Task/ToolTrace/Workspace before peer context.
- sub-agent receives smaller lease and parent trace.
- stable head hash survives profile dynamic changes.

### Acceptance

- profiles govern actual selected context during execution.
- WebUI/API can explain which profile controlled a run.

## Phase 3: Evidence Drilldown Endpoints

### Objective

Every context evidence ref should be inspectable.

### Work

- Add `/api/evidence/resolve?ref=...`.
- Resolve:
  - `tool://...`
  - `workspace://changed-file/...`
  - `workspace://symbol/...`
  - `session://...`
  - `agent://...`
- Return unavailable/degraded result instead of 500 when source is missing.
- WebUI click-to-expand refs.
- TUI refs detail view later in Phase 6.

### Tests

- known tool/session ref resolves from session events.
- unknown ref returns `available:false`.
- workspace refs are bounded and do not read huge files.
- malformed refs are rejected as bad request.

### Acceptance

- Prompt stays compact while raw evidence remains auditable.

## Phase 4: Active Memory Maintenance

### Objective

Move memory from passive recall to active lifecycle maintenance.

### Work

- Add durable maintenance candidate type:
  - conflict
  - stale
  - duplicate
  - authority promotion
  - relationship refresh
- Post-turn records candidates, heavy work is deferred.
- API list/ack/apply/dismiss maintenance candidates.
- WebUI maintenance queue.

### Tests

- conflict candidate can be created and acknowledged.
- stale candidate never deletes underlying memory.
- maintenance failure does not fail the turn.

### Acceptance

- Memory self-organization is explicit, reviewable, and nonblocking.

## Phase 7: Performance And Failure Hardening

### Objective

Quantify enterprise stability.

### Work

- Large session event query tests.
- Large context envelope assembly tests.
- Large workspace bounded scan tests.
- WebUI timeline render tests.
- Failure injection:
  - DB unavailable
  - malformed event JSON
  - huge tool output
  - missing workspace file
  - agent timeout

### Tests

- all failure paths degrade.
- query plans stay indexed.
- no service/tmux residue after e2e.

### Acceptance

- System stays usable under large and partially broken state.

## Implementation Ledger

### Completed

- Initial plan created.
- Phase 1 backend cut:
  - API turns emit `RuntimeRun` started/completed events.
  - `GET /api/sessions/:id/runs` returns paged run events.
  - WebUI API has `runtimeRuns()`.
- Phase 1 WebUI cut:
  - Context panel shows recent RuntimeRun events with status/profile/run id.
- Phase 1 run/context association:
  - persisted ContextEnvelope events include `run_id`.
  - context history DTOs expose `run_id`.
  - WebUI context timeline renders the associated run id.
- Phase 2 runtime profile foundation:
  - `ConversationRuntime` has an active context profile setter/getter.
  - runtime envelope assembly uses the active profile and matching mode.
  - API message turns switch to `YoloGoal` when the current durable task is yolo.
  - sub-agent runtimes are initialized with `SubAgent` profile.
- Phase 3 evidence resolver foundation:
  - `GET /api/evidence/resolve?ref=...` resolves tool/session/workspace refs with bounded payloads.
  - unsupported or unavailable refs return explicit degraded/unavailable responses.
  - WebUI API has `resolveEvidence()`.
- Phase 3 WebUI cut:
  - selected context evidence refs are clickable.
  - resolver payloads render inline with bounded JSON preview.
- Phase 2 CLI profile binding:
  - interactive turns bind `MainTurn`, `SoloGoal`, or `YoloGoal` before provider execution.
  - `/resume` marks the next model turn as `Resume` without misclassifying normal follow-up turns.
  - internal review/helper prompts bind `Review`.
  - non-interactive prompt mode binds solo/yolo profiles and does not infer resume from stored messages.
- Phase 3/6 TUI evidence navigation:
  - context panel can open an evidence detail section with `e`.
  - `n`/`p` navigate refs and `Esc` closes details.
  - detail view shows ref type and associated selected context preview.
- Phase 4 maintenance foundation:
  - memory crate defines reviewable lifecycle maintenance candidates.
  - scans detect stale, duplicate, conflict, authority promotion, and relationship refresh candidates.
  - candidates use explicit open/acknowledged/applied/dismissed lifecycle.
  - `CognitiveContextManager` exposes scan/list/transition methods.
  - API exposes maintenance list, scan, and status transition endpoints.
  - WebUI Memory panel shows the maintenance queue with scan/ack/dismiss controls.
- Phase 5 WebUI runtime console:
  - added a dedicated Runtime tab and `/runtime` slash command.
  - console aggregates active context, runtime runs, pressure metrics, and memory maintenance.
  - console has an intent/profile inspector and refresh control.
- Phase 6 TUI runtime activity:
  - added `RuntimeActivityPanel` as the first sidebar tab.
  - panel summarizes profile, session, context pressure, selected/omitted counts, hashes, and recent timeline activity.
- Phase 7 hardening slice:
  - API tests cover memory maintenance disabled/degraded behavior.
  - API tests cover scan and explicit candidate status transition.
  - memory maintenance large-scan test enforces candidate caps.
  - API test covers invalid maintenance status handling without affecting disabled-memory degradation.
