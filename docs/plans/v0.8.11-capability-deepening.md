# Cowd v0.8.11 Capability Deepening Plan

## Scope

本计划承接 v0.8.10 最终 gate 之后的非 blocker 深化任务。依赖风险项暂不处理；`imap 3.0.0-alpha.15` 的进一步替换或回退不进入本轮。

## Priority Ranking

排序依据：

- Value：对连续 AI、企业可用性、可观测性、交互质量的贡献。
- Complexity：实现范围、耦合面、测试成本。
- Parallelism：是否可与其他 lane 并行推进。

| Rank | Board | Value | Complexity | Parallelism | Reason |
|---|---|---:|---:|---:|---|
| 1 | Task phase/audit engine | 10 | 5 | 8 | 直接支撑 `--yolo` 连续执行、阶段验收、恢复解释，是所有交互层共同消费的核心事实源。 |
| 2 | Release observability scenarios | 9 | 4 | 9 | 用脚本和 gate 固化质量收益，快速提高稳定性，避免后续重构回退。 |
| 3 | WebUI live workbench matrix | 8 | 6 | 7 | WebUI 已有 mocked E2E，需要补真实后端场景，直接提升企业产品可信度。 |
| 4 | TUI unified cockpit timeline | 8 | 7 | 6 | 价值高，但依赖 Task/Memory/Event DTO 稳定；应在 task phase DTO 后深化。 |
| 5 | CognitiveKernel recall explain | 8 | 8 | 5 | 记忆能力关键，但需要更多 memory 内部接口梳理和评测集，适合分阶段薄切片。 |
| 6 | Tool parity stubs | 6 | 6 | 8 | 重要但不阻塞当前 AI 主路径；AskUserQuestion/McpAuth/RemoteTrigger 可拆成独立实现。 |

## Parallel Execution Lanes

Lane A：Task Phase/Audit

- Owner surface：`task_kernel.rs`, `api_routes.rs`, TUI status, WebUI Agents panel。
- Output：phase records、acceptance、test commands、artifacts、review result、audit events。
- Can run in parallel with Lane B release scripts after DTO stabilizes.

Lane B：Release Observability

- Owner surface：`scripts/release_gate.sh`, new scenario scripts。
- Output：task phase DB/file assertion、memory degraded script、WebUI live smoke、cleanup checks。
- Can start with skeleton immediately, then plug Lane A/C assertions.

Lane C：WebUI Matrix

- Owner surface：`webui/*.js`, Playwright specs, optional daemon test harness。
- Output：auth/session/message/task/memory/audit/workspace scenario matrix。
- Can run after Lane A APIs expose phase DTO.

Lane D：TUI Cockpit

- Owner surface：TUI `App`, `ChatView`, status bar, command palette。
- Output：unified filtered event timeline for task/tool/memory/approval。
- Should consume Lane A Task DTO and existing memory status DTO.

Lane E：CognitiveKernel

- Owner surface：memory status/recall explain/write APIs。
- Output：recall explain DTO, degraded audit, long-task memory writes。
- Can develop behind stable DTO and unit tests.

Lane F：Tool Parity

- Owner surface：runtime/tools/slash command handlers。
- Output：AskUserQuestion live I/O, McpAuth UX, RemoteTrigger HTTP client。
- Mostly independent; lower priority than AI workflow core.

## Phase 1: Task Phase/Audit Engine

Goal：

- 把 durable task 从单状态扩展成可审查的 phase/audit 事实源。

TDD first：

- `TaskKernel` starts a phase with objective/plan/acceptance/test commands.
- phase can record artifacts and review result.
- current task DTO exposes current phase summary and audit tail.
- repeated failures still move task to blocked without losing phase records.
- WebUI Agents panel renders current phase and review status.

Implementation：

- Extend `TaskRecord` with `phases: Vec<TaskPhaseRecord>`.
- Add `TaskPhaseRecord`: id/name/objective/plan/acceptance/test_commands/artifacts/review_result/status/timestamps。
- Add Kernel methods: `start_phase`, `record_phase_artifact`, `review_phase`。
- Add API routes:
  - `POST /api/tasks/:id/phases`
  - `POST /api/tasks/:id/phases/:phase_id/artifacts`
  - `POST /api/tasks/:id/phases/:phase_id/review`
- Update WebUI task panel to show current phase, tests, artifacts, review.

Acceptance：

```bash
cargo test -p cowd-cli task -- --nocapture
cargo test -p cowd-cli api_routes::tests::task -- --nocapture
cd webui && npm test
cd webui && env PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/snap/bin/chromium npm run test:e2e
```

## Phase 2: Release Observability Scenarios

Goal：

- 把关键能力从单元测试提升到场景脚本和 gate 断言。

TDD first：

- task phase scenario creates task, starts phase, writes artifact/review, asserts persisted JSON.
- memory degraded scenario asserts API/UI show degraded reason without blocking.
- cleanup scenario asserts tmux/ports/temp dirs clear.

Implementation：

- Add `scripts/task_phase_scenario.sh`。
- Add `scripts/memory_degraded_scenario.sh` if backend hook exists; otherwise mocked WebUI scenario plus API unit contract。
- Wire scripts into `scripts/release_gate.sh`。

Acceptance：

```bash
bash -n scripts/release_gate.sh
scripts/task_phase_scenario.sh
make release-gate
```

TDD first：

- render task phase and memory degraded state.
- audit panel loads records.

Implementation：

- Add stable test fixture config and temp `COWD_CONFIG_HOME`。
- Ensure web server and backend cleanup.

Acceptance：

```bash

scripts/release_gate.sh
```

## Phase 4: TUI Unified Cockpit Timeline

Goal：

- TUI 从 status-only 升级为可过滤的 task/tool/memory/approval event cockpit。

TDD first：

- App can append task phase events to timeline.
- status bar shows task phase + memory degraded.
- key/filter tests can select task/tool/memory event groups.
- tmux smoke sees task phase status.

Implementation：

- Add stable `TuiEventKind` filter model.
- Map TaskKernel audit events into timeline entries.
- Add compact task phase panel/section.

Acceptance：

```bash
cargo test -p cowd-cli tui:: -- --nocapture
scripts/tui_smoke.sh
```

## Phase 5: CognitiveKernel Recall Explain

Goal：

- 让 memory 不只是状态可见，而是召回来源、降级路径和长任务贡献可解释。

TDD first：

- recall explain DTO includes source layer, score, mode, degraded reason.
- long task writes decision/todo/failure memory records.
- degraded memory does not block API/TUI/WebUI.

Implementation：

- Add `CognitiveKernel` facade or extend current memory API facade.
- Add `/api/memory/recall/explain`。
- Feed Task phase transitions into memory write path.

Acceptance：

```bash
cargo test -p cowd-memory recall -- --nocapture
cargo test -p cowd-cli memory -- --nocapture
```

## Phase 6: Tool Parity Stubs

Goal：

- 消除高价值 user-facing stubs。

TDD first：

- AskUserQuestion returns structured prompt request.
- McpAuth reports auth URL/status and allows completion callback.
- RemoteTrigger sends HTTP request with timeout/error mapping.

Implementation：

- Prioritize AskUserQuestion, then RemoteTrigger, then McpAuth.
- Keep TestingPermission as test-only low priority.

Acceptance：

```bash
cargo test -p tools parity -- --nocapture
cargo test -p cowd-cli mock_parity -- --nocapture
```

## Completion Policy

每个 phase 必须满足：

- Contract/unit tests pass.
- Scenario or browser/tmux test exists when UI/service behavior is involved.
- Logs/ports/tmux/temp files cleaned.
- Plan record updated with commands and result.
- Commit after phase acceptance.
