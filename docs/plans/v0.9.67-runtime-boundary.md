# v0.9.67 Runtime Boundary

## Goal

Create the first stable runtime boundary without breaking existing CLI, TUI,
WebUI, daemon, session, memory, context, or channel behavior.

## Implementation

- Added `runtime_protocol` as the shared local command schema foundation.
- Added `runtime_boundary` for lightweight daemon runtime status/snapshot types.
- Added `runtime_service` as the first daemon runtime facade.
- Routed low-risk socket control commands through `RuntimeService`:
  - `status` / `runtime.status`
  - `runtime_snapshot` / `runtime.snapshot`
  - `list_sessions` / `session.list`
  - `acquire_session_lease` / `session.lease.acquire`
  - `release_session_lease` / `session.lease.release`
- Kept `chat`, `chat_stream`, `create_session`, and model execution on the
  existing path for this version.
- Added explicit protocol-version rejection while preserving the existing
  legacy socket response shape.
- Unified LiveCli provider initialization with the existing prompt path.
- Fixed provider fallback loading to respect the active Cowd config home.
- Hardened provider-registry tests that mutate global provider state.

## Validation Targets

- Protocol serialization and unsupported-version behavior.
- Runtime service status and snapshot without model/provider bootstrap.
- Lease projection through the runtime service facade.
- TUI live session switching with explicit provider config.
- Fast/core/full segmented validation.

## Non-goals

- No crate extraction in this version.
- No chat execution migration in this version.
- No WebUI API route restructuring in this version.
