# Cowd v0.8.18 Runtime Closed Loop Plan

v0.8.18 turns the v0.8.17 runtime event kernel from a projection layer into a
closed loop. The priority is to connect existing high-value primitives instead
of adding heavy subsystems.

## Goals

- Agent collaboration must emit auditable runtime events and work graph refs.
- Memory pulse must consume runtime events and enqueue reviewable candidates.
- Runtime events must carry enough refs/status to drive TUI/WebUI projection.
- Large file risk must keep shrinking through behavior-preserving module splits.
- Evaluation gates must include unit, API, live TUI, live WebUI, and cleanup.

## Phases

### Phase 1: Version And Contract

- Bump workspace to `0.8.18`.
- Add this plan.
- Keep v0.8.17 plan as historical design record.

Acceptance:

```bash
cargo metadata --no-deps --format-version 1 | rg '"version":"0\.8\.18"'
```

### Phase 2: RuntimeEvent To MemoryPulse

- Add a deterministic converter from `RuntimeEvent` payloads to
  `MemoryPulseBatch`.
- Supported payloads:
  - `maintenance_candidates`
  - `candidates`
  - collaboration review packets
- Invalid or irrelevant events must return `None`, not fail globally.

Acceptance:

```bash
cargo test -p cowd-memory memory_pulse -- --nocapture
```

### Phase 3: AgentWorkGraph Runtime Events

- Add graph event emission helpers:
  - `agent.workgraph.planned`
  - `agent.workgraph.reviewed`
- Include refs for graph, board, parent run, agent runs, and context envelopes.
- Preserve existing graph model and tests.

Acceptance:

```bash
cargo test -p runtime agent_workgraph -- --nocapture
```

### Phase 4: Session Kernel Integration

- Add session-level helpers to persist WorkGraph and MemoryPulse reports as
  runtime events.
- Missing stores must degrade cleanly.

Acceptance:

```bash
cargo test -p cowd-cli runtime_closed_loop -- --nocapture
```

### Phase 5: Projection And UI

- Expose work graph and memory pulse events through the existing runtime
  timeline projection.
- Keep WebUI using one Runtime Console surface.

Acceptance:

```bash
cd webui && npm test
```

### Phase 6: Boundary Governance

- Continue splitting only event-kernel-owned API handlers out of
  `api_routes.rs`.
- Do not mix behavior changes with file movement.

Acceptance:

```bash
cargo check -p cowd-cli
git diff --check
```

### Phase 7: v0.8.18 Gate

- Add `scripts/v0818_eval.sh`.
- Default gate covers unit/API/WebUI checks.
- Live gate covers TUI tmux and WebUI Chromium scenarios.

Acceptance:

```bash
scripts/v0818_eval.sh
COWD_V0818_LIVE=1 scripts/v0818_eval.sh
```

## Non-Goals

- No new database engine.
- No separate graph service.
- No heavy scheduler rewrite before runtime events prove the closed loop.
