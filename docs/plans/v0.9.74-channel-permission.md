# v0.9.74 Channel Permission Runtime

## Goal

Close the highest-risk channel/permission gap: cross-channel and connector service actions must share one permission semantics.

## Implemented Scope

- Separated policy evaluation from grant consumption.
- `preflight`, `policy/simulate`, and `dry_run` preserve single-use grants.
- `commit` execution consumes a single-use grant only after actual dispatch/service execution succeeds.
- Connector service execution records audit envelopes with consumption evidence.
- Mock Docs and Feishu read-only service execution now both attach audit receipt IDs.
- Added real gateway scenario for permission lifecycle:
  - create single-use grant;
  - preflight and dry-run do not consume;
  - commit consumes;
  - audit records consumed grant evidence.
