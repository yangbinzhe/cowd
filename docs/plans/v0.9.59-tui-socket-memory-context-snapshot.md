# v0.9.59 TUI Socket Memory/Context Snapshot

## 目标

将 TUI 主工作台的 memory 与 context 状态读取纳入 daemon Unix socket 快路径，HTTP projection 仅作为降级补救。该阶段不把完整 context envelope 搬进控制通道，只暴露 TUI 需要的轻量可用性摘要，避免控制路径变重。

## 设计边界

- `memory_status`：daemon socket 复用现有 HTTP memory status 聚合逻辑，并补充 `ok/kind` 控制协议字段。
- `context_snapshot`：daemon socket 返回当前 session 的轻量运行态摘要，包括 runtime 是否活跃、是否已有 context envelope、基础计数和降级原因。
- TUI `RuntimeControlSnapshot` 刷新时优先调用 socket；socket 不可用时回退 HTTP projection，并记录降级原因。
- WebUI 与 HTTP API 保持现状，不改变外部 HTTP 响应契约。

## TDD 验收

1. `DaemonControlClient` 测试必须验证 `memory_status` 与 `context_snapshot` 的 socket 命令格式。
2. daemon socket 响应必须包含 `ok: true`，保证 TUI 控制客户端统一拒绝处理逻辑可用。
3. TUI 刷新逻辑必须保留 HTTP fallback，daemon 未运行或 socket 暂不可用时不能阻塞整体主工作台。
4. `cargo fmt --check` 与 `git diff --check` 必须通过。

## 评价标准

- TUI memory/context 状态不再依赖 HTTP 作为首选路径。
- context 控制面保持轻量，不引入完整上下文组装开销。
- 失败局部降级，不能造成 TUI 全局刷新失败。
