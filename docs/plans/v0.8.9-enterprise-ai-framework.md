# Cowd v0.8.9 Enterprise AI Framework Plan

## 目标

v0.8.9 的目标不是继续堆模块，而是把已有能力接成企业级闭环：

- 单一事实源：Session、消息、事件、记忆、配置必须有明确 owner，禁止双源漂移。
- 主动认知：记忆系统从被动检索升级为后台摄入、预取、维护、审计。
- 可靠会话：WebUI/TUI/API/平台入口共享同一 Session 生命周期和持久化模型。
- 高性能交互：TUI 和 WebUI 以流式事件为核心，长上下文和长工具输出不阻塞主交互。
- 可验收交付：每个阶段必须有编译、单测、集成、交互、性能验收。

## 当前审计结论

### 已确认的现实问题

1. WebUI 双源漂移：`webui/index.html` 是 legacy DOM，但加载了 `assets/js/*` 新组件脚本；实际服务目录缺少匹配 legacy DOM 的根级脚本。
2. WebUI API 契约断裂：前端把 `/api/sessions` 当数组，后端返回分页对象；前端把 `/messages` 当数组，后端返回分页对象。
3. WebUI SSE 方法错误：前端使用 `POST /api/sessions/:id/stream`，后端只提供 `GET` SSE。
4. Session 事实源不统一：`ActiveSessions`、`runtime::Session`、`memory::UnifiedSessionStore` 并存，创建和列表路径曾经不一致。
5. Runtime 支持 `with_session_store()` 双写，但 API runtime 构造未注入 store，导致 SQLite 消息持久化链路不闭合。
6. Memory 设计完整但集成不足：L4、ToolSandbox、代码符号-记忆链接、后台摄入、预测预取等能力存在未启用或未消费路径。
7. TUI 组件数量多，但事件、布局、背压、Memory/L4 数据源未形成统一产品级体验。

### 本轮已完成的 P0 止血

1. 恢复顶层 WebUI 根级脚本，`index.html` 回到与 legacy DOM 匹配的入口。
2. 修复 WebUI `listSessions()` 和 `getMessages()` 返回值归一化。
3. 修复 WebUI SSE 为 GET，并兼容 `TextDelta`、`ThinkingDelta`、`ToolStart`、`ToolComplete`、`TurnComplete`。
4. API 创建 session 时同步写入 `UnifiedSessionStore`，避免新建会话在列表中消失。
5. API turn 完成后将 runtime session 快照同步到 SQLite messages，恢复刷新/重启后的历史消息读取。
6. API 删除 session 支持 active runtime 和 SQLite 历史会话两种路径。

## v0.8.9 目标架构

```
TUI / WebUI / CLI / Platform
        |
        v
Gateway API + SessionEventBus + Auth + Backpressure
        |
        v
SessionKernel
  - Active runtime registry
  - Lifecycle manager
  - SQLite message/event store
  - JSONL compatibility importer only
        |
        v
ConversationRuntime
  - Provider stream
  - Tool orchestration
  - Permission gates
  - CowdEvent bus
        |
        v
CognitiveKernel
  - prepare_context
  - on_turn_end
  - background ingestion
  - L4 shared layer
  - ToolSandbox recall
  - code symbol memory graph
```

核心原则：

- `UnifiedSessionStore` 是 Session 元数据、消息、事件、搜索的持久化事实源。
- `ActiveSessions` 只保存热 runtime，不承担持久事实源职责。
- JSONL 进入兼容和迁移层，不再作为新功能主路径。
- WebUI/TUI 不直接猜测数据结构，全部通过稳定 API DTO。
- Memory 不再只在 turn 开始/结束被动调用，必须有后台摄入和变更通知。

### Phase 1: SessionKernel 统一

改造：

- 新增 `SessionKernel` 或 `SessionService`，统一封装 `ActiveSessions + SessionLifecycleManager + UnifiedSessionStore + SessionEventBus`。
- `build_runtime()` 增加可选 `UnifiedSessionStore` 参数，真正使用 runtime 内置 `with_session_store()`，移除 API handler 的临时快照同步。
- `GET /api/sessions/:id` 对冷 session 支持 lazy hydrate，必要时从 SQLite 重建只读 session view。
- 生命周期 API：close、pause、resume、fork、compact、stats。
- 事件溯源：将 TurnStarted、TextDelta、ToolStart、ToolComplete、TurnComplete、TurnError 写入 `session_events`。

验收：

- API 创建的 session 必须立即出现在列表。
- turn 过程消息必须按 sequence 写入 SQLite。
- 进程重启后 session 列表、消息、搜索可用。
- 并发 20 session 发送消息不出现 registry/store 不一致。

当前进展：

- API runtime 构造已注入 `UnifiedSessionStore`，会话创建/list/delete/message read 进入统一 store。
- `POST /api/sessions` 和 `GET /api/sessions/:id` 优先返回 `UnifiedSessionStore` 元数据，active session 不再降级成缺少 model/title/timestamps 的内存简略对象。
- Runtime `dual_write_message()` 现在不只写 `messages`，还会追加 `message_appended` 到 `session_events`。
- API turn 完成后会确定性同步 runtime session 快照到 SQLite，补齐 `messages` 和缺失的 `message_appended` events，避免 `spawn_blocking` 路径下后台双写丢失。
- 新增 `GET /api/sessions/:id/events?from_seq=0&limit=100`，返回统一事件 DTO：`session_id/type/sequence/created_at_ms/payload`。
- 事件 payload 保存 role、sequence 和完整 message JSON，为断线回放、审计、TUI/WebUI 时间线诊断提供持久事实源。
