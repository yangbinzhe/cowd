# v0.9.89 IACC Evidence And Insight Quality Gates

## Goal

Add the first governed quality gate for IACC evidence and operational insight.
The system must be able to distinguish "has source and metric evidence but has
not completed attribution" from "ready for governed decision/action".

This version deliberately keeps the gate deterministic and inspectable. It does
not ask an LLM to decide whether evidence is good enough. The runtime evaluates
the structured evidence packet itself, persists the decision, and exposes the
result through the gateway API.

## Runtime Contract

New contract:

- `IaccQualityGateDecision`

The gate currently evaluates:

- source references;
- metric evidence;
- change evidence;
- attribution candidates;
- impact paths;
- packet confidence.

Decision levels:

- `fail`: evidence is not enough to proceed;
- `review`: evidence exists, but attribution or impact analysis is still
  missing;
- `pass`: evidence, attribution, impact, and confidence are ready for governed
  operating review.

## Store

Schema version is now `9`.

New table:

- `iacc_quality_gate`

New store capabilities:

- `evaluate_evidence_quality`
- `get_quality_gate`

Health now reports:

- `quality_gate_count`

## API

New routes:

- `POST /api/iacc/evidence/:id/quality-gate`
- `GET /api/iacc/quality-gates/:id`

New health capabilities:

- `evidence_quality_gate`
- `insight_quality_gate`

## Acceptance

Runtime tests prove:

1. an evidence packet built from metric/change evidence is `review` before
   incident analysis;
2. the review gate requires `run_incident_analysis`;
3. after incident analysis enriches the packet with attribution and impact
   paths, the same packet receives a `pass` gate;
4. gate decisions are persisted and counted in health.

Scenario script:

```text
scripts/v0989_iacc_quality_gate_scenario.sh
```

The gateway scenario proves through API:

1. schema version 9 is exposed;
2. quality-gate capabilities are visible;
3. facts can still be ingested and metrics recomputed;
4. a pre-analysis evidence packet returns `review`;
5. incident analysis updates the evidence packet with insight outputs;
6. a post-analysis gate returns `pass`;
7. both quality gate records can be retrieved;
8. health reports `quality_gate_count: 2`.

## Role In The IACC Roadmap

This version closes the first governance gap in the structured-data brain:
IACC no longer treats every evidence packet as equally actionable. Later
versions should attach these gates to action execution, cockpit cards, report
generation, and cross-plane command bridges so that high-risk decisions cannot
skip deterministic evidence and insight checks.

## Next Version
