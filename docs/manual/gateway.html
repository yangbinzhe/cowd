GATEWAY、API 与 SURFACE

一个服务入口，一份执行真相，多种交互方式

Gateway 承担认证、路由、投影、静态资源、外部进程与可靠消息托管。它通过 RuntimeService 调用 Runtime，通过 SurfaceHost 管理 Edge，通过 AppHost 装载审核过的业务 APP。所有前端和渠道消费同一组能力合同。

内部组成

API 的三种投影

入口用途主要消费者
GET /api/gateway/capability-contract运行时真实能力、版本、状态与治理语义TUI · WebUI · operators
GET /api/gateway/openapi.json由 Route Registry 生成的机器接口规范客户端生成、调试、文档
GET /api/gateway/openai-tools面向模型的可调用能力投影AI 工具发现

三者来自同一 Route Manifest，不应手工维护三套清单。人类说明书解释关系和操作，机器合同负责精确字段与版本。

主要接口族

Session / Task / Mission

会话历史、输入队列、执行策略、任务绑定、Mission 全景和调度。

Runtime / Agent / Team

执行控制、定义目录、实例、运行图、活动详情、实时状态和取消。

Context / Memory / Reality

上下文信封、召回报告、分层记忆、治理状态、事实决策和证据。

Matrix / Apps

实体、关系、指标、SourcePack、快照、场景和 APP 合同/操作。

Tools / Skills / MCP

工具目录、诊断、技能检查/安装/运行、MCP 生命周期和投影。

Edges / Surfaces / Connectors

发现、配置、健康、修复、可靠消息、数据源资源和回调。

实时数据如何到达前端

Runtime durable event / hot-state revision
  → canonical projection reducer
  → Gateway snapshot + delta + heartbeat
  → one physical SSE stream, multiple logical sources
  → WebUI / TUI reducer
  → resync only when epoch or revision contract requires it
  • SSE 是服务到客户端的实时投影，客户端命令继续使用 HTTP；这允许多个独立客户端同时观察。
  • 快照建立基线，delta 只应用到确认的 revision；越过确认 revision 时要求定向 resync，不能静默猜测。
  • 默认关闭的 WebUI 右侧面板不加载活动图、证据或工作区数据；打开后再订阅对应 source。

APP 宿主边界

APP 只能来自审核过的 `apps/catalog.toml` 和固定 source lock。编译时组合 Bundle，启动时根据配置启用，运行时由 Host 提供认证后的请求、存储租约、实时订阅和 Surface contribution。APP 不能运行时拉取源码，也不能持有 Gateway 或 Runtime 私有句柄。
