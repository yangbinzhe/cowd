REALITY CORE

让上下文可选择，让事实可追溯，让历史不丢失

Reality Core 不是第二个 Runtime。Fact Kernel 定义事实语义，Memory 管理非结构化与时序知识，Matrix 管理实体、关系、指标和证据。Runtime 在每轮执行中按目标生成召回请求，并把选中的内容编译进 Context Envelope。

三类能力的关系

记忆分层与隔离

层内容默认作用域召回条件
L0身份、不可丢失规则、明确约定用户 / Agent与当前身份匹配，稳定头部
L1高显著性核心事实与长期偏好用户或组织目标相关、权威有效
L2项目决策、代码事实、局部约束Workspace / Project当前工作区或显式关联项目
L3长文档、案例、原始过程与深层知识知识域 / 来源集合语义、关键词、图关系触发后按需展开
L4团队运行时共享摘要与已批准产物Team / Mission仅共享被标记的内容，不复制全部私有上下文

隔离不是物理分库的同义词。每个条目携带 tenant、workspace、project、session、agent/team、来源和可见性标签；召回先硬过滤作用域，再做混合排序，最后经过一致性和预算门禁。

解析真实窗口

显式模型配置优先，其次模型目录与 Provider 能力，未知模型使用 128K 兜底；较小的服务端限制可在运行时校准。

BudgetPolicy
B
保护必需内容

系统规则、用户当前输入、最近未完成工作、授权与任务身份优先进入稳定头部或必需区。

ContextRuntime
C
相关性召回

Memory 与 Matrix 返回候选、证据和省略索引；不是把数据库全部塞入 Prompt。

RealityRecall
D
语义检查点

接近硬容量时把旧历史压缩成带来源引用的检查点，保留近期原文；原始消息和工具产物仍在耐久存储中可下钻。

Compression
“永不丢失”不等于“每轮全部注入”

完整历史、工具原始输出、证据与附件必须耐久保存；热上下文只保留当前解题所需内容和可展开索引。这样同时保护连续性、精度和 Provider 延迟。

冲突、权威与自动治理

  • 写入路径执行内容哈希与幂等去重，避免同一记忆和知识反复保存。
  • 事实比较同时看来源权威、观察时间、有效时间、置信度和适用作用域；“最新”只在同一语义和权威层级内优先。
  • 可证明、可逆的低风险合并可以自动执行；同权冲突、全局晋升和证据不足进入审批。
  • 后台治理按启动延迟和本地时段运行，手动全盘扫描与后台任务互斥并报告处理数量、问题和证据。

Matrix 适合解决什么

结构化事实

实体、关系、来源事实、证据包和本体概念具有稳定 ID 与血缘。

指标与影响分析

指标定义、依赖图、查询计划、质量门禁和影响路径形成可复算结果。

外部数据快照

Edge 返回标准批次和候选水位线，Gateway/Matrix 负责 SourcePack 映射、提交和增量一致性。

What-if 场景

Scenario 绑定快照引用、输入假设、计算计划和输出合同，不把模型文字当成结构化真相。

Reality 与进化闭环

运行失败、恢复、工具证据、评测结果和策略效果可投影为 Growth Signal，但它们不会直接改写生产能力。候选经过诊断、方案、隔离实现、Eval 对比和治理审批，才能发布新的 Agent、Skill、Tool、策略或 Runtime 版本。

runtime evidence
  → growth signal
  → diagnosis / candidate
  → isolated implementation
  → harness-eval comparison
  → review and approval
  → versioned promotion or rejection
