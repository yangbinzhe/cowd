系统总览

AI Harness 的运行内核与统一控制面

Cowd 将对话、任务、团队、工具、上下文、现实数据和外部入口组织成一条可恢复、可审计、可扩展的执行链。Core 负责执行真相，Edge 负责连接外部世界，业务 APP 只消费内核能力。

Core 0.9.671 Rust 2021 API HTTP + SSE Storage SQLite / PostgreSQL

一张图理解整个系统

箭头表示运行调用方向，虚线表示编译期或合同关系。Runtime 不持有 Surface，Surface 也不重建执行状态。

三个代码库，各自只拥有一种变化

Cowd Core

拥有合同、Runtime、Gateway、TUI、Reality Core、工具与通用 APP 宿主。

Cowd Edge

拥有 WebUI、外部消息适配器、数据源连接器和平台 SDK；不链接 Runtime。

Cowd MFG APP

拥有制造领域模型、业务合同、工作流和界面贡献；通过 App SDK 消费 Core。

核心能力地图

执行与协同

模型提出策略、团队和依赖，Runtime 校验并编译 ExecutionGraph，按依赖并发执行。

Session 与 Mission

Session 管对话历史，Task 管可验收工作，Mission 聚合长期目标；关系通过持久绑定派生。

上下文与现实

动态预算、语义压缩、分层记忆、事实权威和结构化 Matrix 共同提供任务相关上下文。

工具、技能与 MCP

Tools 是薄动作，Skill 是可复用方法包，MCP 是外部工具协议；权限在 Runtime 执行点统一裁决。

Gateway 与实时投影

Gateway 暴露 HTTP/SSE、能力合同、审批、执行图、会话历史和 Edge 生命周期。

评测与进化

运行证据进入 Eval、Growth 与候选治理；高风险晋升必须经证据比较和人工发布门禁。

必须保持的设计不变量

  1. Runtime 是模型循环、协同调度、权限执行和状态提交的唯一权威。
  2. Gateway 是统一外部入口和投影层，不重建业务判断，也不直接执行对话循环。
  3. Surface 与 Edge 只消费合同和投影，不能持有 Runtime、Provider 或 Memory 生命周期。
  4. Tools 不规划任务；Skill 不接管 Agent 生命周期；APP 不进入内核。
  5. 数据库保存耐久事实，运行中热状态由 Runtime 内存面负责；恢复必须可由事件与检查点重建。
