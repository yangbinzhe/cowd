快速使用与运维

先验证控制面，再开始业务操作

日常使用只需要管理配置、Gateway 生命周期和 Surface 状态。CLI 不提供旧式 REPL、run_prompt 或第二套对话循环；TUI、WebUI 和外部渠道都通过 Gateway 使用 Runtime。

最短健康路径

cowd config doctor
cowd doctor

cowd gateway start
cowd gateway status
cowd gateway doctor

cowd gateway open
cowd

`cowd` 无子命令时进入 TUI；默认开发构建可以不包含 TUI，正式 `full` 构建才组合终端 Surface。Gateway 默认监听配置中的 API Server，默认工作区来自 `workspace`。

gateway.platformsAPI Server 与外部消息 Edge 配置配置校验通过后自动重载；拓扑项可能要求重启
凭据不要写进文档或命令历史

优先使用 secretRef、权限为 0600 的用户 secret 文件或运行环境注入。WebUI/TUI 只拿 Gateway 外部凭据，不接触 Provider 和数据库密钥。

Provider 配置技巧

  • 协议可显式设为 `anthropic`、`completions` 或 `responses`；显式设置后不再探测。
  • 模型必须出现在 Provider 的 models 中；别名只来自配置，不存在厂商硬编码别名。
  • 同一 Provider 的多个模型不能隔离余额或凭据故障；高可用 fallback 应跨账号或 Provider。
  • 上下文窗口显式配置优先；未知模型按 128K 窗口和 64K 最大输出估算。

存储迁移与验证

cowd storage plan
cowd storage upgrade
cowd storage verify

SQLite 与 PostgreSQL 是二选一的全进程主后端，不是双写互补模式。PostgreSQL 使用统一 PoolSet 和 critical、online-read、background 三条 lane；APP 复用宿主租约，不创建私有连接池。
