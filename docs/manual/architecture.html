架构与边界

用所有权而不是目录数量理解 Cowd

每个 crate 只应承担一种稳定变化：合同定义语义，Runtime 承担生命周期，Gateway 暴露服务，Reality Core 保存事实，Edge 连接外部，APP 组织领域体验。

合同、端口与实现

判断一个依赖是否合理

问三个问题：谁拥有生命周期，谁定义稳定语义，替换实现时谁应该保持不变。若调用者需要导入被调用者的私有生命周期类型，边界通常已经泄漏。

修改代码时的快速判定

  1. 新增执行语义：先改 harness-contract，再由 Runtime 实现，最后投影到 Gateway/Surface。
  2. 新增平台接入：放到 Edge，通过 surface.json 和 Edge v2 合同注册，不给 Core 增加平台 SDK。
  3. 新增领域功能：做成 APP contribution，APP 只拿 SDK、存储租约和公开事实合同。
  4. 新增工具：Tools 实现原子动作，Runtime 负责选择、授权、并发和证据；不要让 Tool 启动 Agent。
  5. 新增状态：先判断它是热运行态、耐久事实还是只读投影，避免同一事实多写。
