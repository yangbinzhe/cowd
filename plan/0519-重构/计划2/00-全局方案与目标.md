# Cowd 全局重构方案 — 计划2

> 版本：v2.0 | 日期：2026-05-19
> 综合：前两次分析 + GitNexus 第三次深度分析 + AI 架构师全局视角

## 一、总体目标

### 使命

将 Cowd 从"功能可用"提升到"工程卓越"：
- **代码质量**：main.rs 从 9000+ 行拆分为 15+ 个独立模块
- **架构清晰**：引入 3 层抽象（存储/事件/运行时）
- **测试覆盖**：核心模块测试覆盖率从 40% → 80%
- **文档完整**：每个新模块有 rustdoc + 架构图
- **性能指标**：TUI 渲染 < 16ms/frame，Server 支持 1000 并发 SSE

### 核心理念

1. **抽象先行**：先定义 trait，再实现 —— 每个组件可替换
2. **事件驱动**：所有 UI（TUI/WebUI/CLI）通过统一 EventBus 通信
3. **存储无关**：JSONL→SQLite→PostgreSQL 无缝切换
4. **异步优先**：ConversationRuntime async-first，同步是特例
5. **测试先行**：每个模块的重构从测试开始

## 三、实施阶段

| 阶段 | 名称 | 工时 | 模块数 | 核心变更 |
|------|------|------|--------|---------|
| **Phase 0** | 基础抽象层 | 6h | 4 | StorageBackend trait, EventBus trait, 错误类型 |
| **Phase 1** | main.rs 拆分 | 8h | 5 | CLI/TUI/Server 入口分离 |
| **Phase 2** | 存储后端迁移 | 6h | 3 | SQLite 后端, JSONL 导出 |
| **Phase 3** | TUI 事件驱动重构 | 12h | 6 | 消除 stdout 泄漏, 流式渲染 |
| **Phase 4** | Server 异步 + SSE | 6h | 4 | 消除 block_on, 背压控制 |
| **Phase 5** | Agent 协同增强 | 8h | 5 | MCP 协议, 心跳, Worker 持久化 |
| **Phase 6** | 记忆框架优化 | 8h | 4 | 动态压缩, 增量挖掘, 向量解耦 |
| **Phase 7** | 配置统一 | 4h | 2 | 合并 config crate, 热重载 |
| **Phase 8** | 测试补全 | 8h | ALL | 覆盖率 40%→80% |
| **Phase 9** | 文档与清理 | 4h | ALL | rustdoc, 架构图, 死代码删除 |

**总计**: 70h 预估

## 四、并行执行策略

```
   │                           │

```

## 五、风险缓解

| 风险 | 缓解措施 |
|------|---------|
| main.rs 拆分导致回归 | 每个拆分后运行全套单元测试 (cargo test) |
| SQLite 性能不达预期 | 保留 JSONL 作为 fallback，通过 trait 切换 |
| TUI 渲染性能 | 16ms 帧预算，超过则优化 diff 算法 |
| 异步改造阻塞 | 使用 tokio::task::spawn_blocking 包装遗留同步代码 |
| 编译时间增加 | 每个文件 < 500 行，并行编译 |
