## P0 缺陷详细清单

### P0-1: main.rs 巨型单体 (9,000+ 行推测)
- **证据**：run_tui_repl 单一函数调用 19 个模块，LiveCli 40+ 方法
- **修复**：拆分为 cli.rs / tui/mod.rs / server/mod.rs 独立入口
- **验证**：编译时间降低 40%，每个新文件 < 500 行

### P0-2: stdout 与 TUI 渲染冲突（8 个泄漏点）
- **证据**：consume_stream (171行 write! stdout), format_tool_* (println!)
- **修复**：全部改为 TuiEvent channel → ratatui Frame
- **验证**：`cowd 2>/tmp/tui.log` → /tmp/tui.log 为空

### P0-3: 记忆持久化无事务保证
- **证据**：JSONL 追加模式，无原子写入
- **修复**：引入 SQLite 作为主存储，JSONL 为导出格式
- **验证**：并发写测试（10 线程同时写 Session）

### P0-4: 子Agent通信机制单一
- **证据**：仅 stdin/stdout，无心跳/超时/流式
- **修复**：复用 MCP 协议作为 Agent 间通信标准
- **验证**：子Agent 可推送进度更新

### P0-5: 配置系统 **ConfigLoader (runtime) vs UnifiedConfig (config)** 双轨并行
- **证据**：两个独立 crate 的配置加载器，无统一接口
- **修复**：合并到 config crate，定义 ConfigProvider trait
- **验证**：所有配置加载经单一入口

### P0-6: LadybugDB 原生模块兼容性
- **证据**：当前环境 WAL 错误、shadow pages 无法回放
- **修复**：添加纯 Rust 回退存储（SQLite），抽象 StorageBackend trait
- **验证**：无 LadybugDB 环境下功能完整

## P1 缺陷详细清单

### P1-1: TUI/Server 共享同步 Runtime
- **修复**：ConversationRuntime 改为 async-first，CLI 用 block_on 消费
- **验证**：Server 路径不再含 `.block_on()`

### P1-2: 无分布式 Agent 编排
- **修复**：Agent Registry + 消息队列抽象层
- **验证**：可配置跨机器 Worker

### P1-3: Gates 与工具执行集成不完整
- **修复**：ToolExecutionPipeline 自动串入 Gate 链
- **验证**：每个工具调用经过 Gate 检查

### P1-4: 压缩阈值不适应多样化模型
- **修复**：AdaptiveThreshold 动态根据 context_window 计算
- **验证**：qwen-turbo (8K) 和 claude-sonnet (200K) 自动适配

### P1-5: WebUI API 无类型安全
- **修复**：schemars 生成 OpenAPI → TypeScript 类型
- **验证**：typescript typecheck 通过

### P1-6: Server SSE 流无背压控制
- **修复**：channel 容量可配置 + 慢消费者检测
- **验证**：1,000 并发 SSE 连接不 OOM

### P1-7: 跨会话记忆重建性能
- **修复**：GsdStateRebuilder 支持增量重建
- **验证**：50+ 轮对话恢复 < 200ms

### P1-8: 无统一错误处理策略
- **修复**：定义 ErrorChain + 统一错误类型 + 恢复策略注册
- **验证**：所有 API 错误格式一致

## 核心改进建议（架构师视角）

### 建议一：引入抽象层（Adapter Pattern）

```
当前：
  main.rs → ConversationRuntime (同步)
         → start_http_server (异步)
         → TUI event loop (同步)

建议：
  main.rs → RuntimeFacade (async trait)
         ├── TokioRuntime (Server)
         ├── BlockingRuntime (CLI)
         └── EventLoopRuntime (TUI)
```

### 建议二：存储后端解耦

```
当前：
  Session → JSONL file
  Memory → JSONL file + LadybugDB vector
  Config → YAML files

建议：
  StorageBackend trait
  ├── JsonlStorage (legacy, export)
  ├── SqliteStorage (primary)
  ├── PostgresStorage (production)
  └── MemoryStorage (test)
```

### 建议三：事件总线统一

```
当前：
  TUI: mpsc::channel<TuiEvent>
  Server: tokio::broadcast + SSE
  Agent: stdin/stdout

建议：
  EventBus trait (publish/subscribe)
  ├── TuiEventBus → ratatui widgets
  ├── SseEventBus → SSE streams
  └── AgentEventBus → MCP protocol
```
