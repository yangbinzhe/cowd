# Cowd 第三次深度分析 — 记忆框架深度分析

> 基于 GitNexus：crates/memory 36+ 模块，252 个测试，跨 5 层架构

## 1. 记忆系统架构全景

### 1.1 五层记忆（L0-L4）

```
L0 — Identity (身份层)
  ├── 持久化用户身份信息
  ├── 跨会话不变
  └── 初始加载后不再更新

L1 — Essential (核心层)
  ├── 高频高优先级记忆
  ├── token 预算控制 (默认 800 tokens / 15 条)
  └── 自动提取 + 频率衰减

L2 — Project (项目层)
  ├── 项目级上下文和知识
  └── 跨会话共享

L3 — Deep Recall (深度召回层)
  ├── 全文搜索历史记忆
  ├── FTS5 全文索引
  └── BM25 + 混合搜索

L4 — Shared (共享层)
  ├── 团队/组织共享知识
  ├── 跨 Agent 可见
  └── shared_scope 隔离
```

## 2. 设计优点

### 2.1 AAAK 压缩技术（专有）
```
AaakCompressor.compress (29行) → 将记忆注入减少 70-85%
  ├── Abbreviation: 实体名称缩写（如"Cowd"代表"Cowd AI Framework"）
  ├── EntityType: 实体类型分类
  ├── PriorityItem: 优先级标记
  └── GsdContext/GsdState: 上下文状态快照增量编码
```

### 2.2 时序知识图谱
```
temporal_relation() → 为关系三元组添加时间戳维度 (TemporalMarker)
支持：时序推理 + 知识演化追踪 + 时间范围查询 (TemporalQuery)
```

### 2.3 多层检索策略
- **Closet**: 精简指针行索引（RANK_BOOSTS: [0.40, 0.25, 0.15, 0.08, 0.04]）
- **CognitiveContextManager**: 智能构建注入到 system prompt 的记忆上下文块
- **ContextFence**: 规则过滤防止注入无关记忆

## 3. 缺陷与弊端

### 🔴 P0: 记忆持久化单一故障点
**问题**：当前所有记忆存储在 JSONL 文件中，无事务保证。
**影响**：并发写时可能数据损坏，大项目下 IO 成为瓶颈。
**GitNexus 数据**：write_guard 试图通过子Agent审计解决，但只是日志非实际锁。

### 🔴 P0: 向量索引与 LadybugDB 耦合
**问题**：Embedding 管线直接依赖 LadybugDB 的向量扩展。
**影响**：当 LadybugDB 不可用时（如当前环境），所有预计算向量丢失。
**建议**：添加外部向量存储（SQLite + pgvector / Qdrant）作为备选后端。

### 🟡 P1: 压缩阈值不适应小模型
**问题**：AdaptiveThreshold 的 small_model/large_model 使用固定阈值。
**影响**：在 qwen-turbo (8K 上下文) vs claude-sonnet (200K) 间自动适配不足。
**GitNexus 数据**：monitor.rs 中 AdaptiveThreshold.for_model 仅有简单分支。

### 🟡 P1: 跨会话状态重建性能
**问题**：GsdStateRebuilder.quick_rebuild 在大型会话恢复时需全量扫描。
**影响**：恢复 50+ 轮对话时耗时 > 2s。

### 🟢 P2: 记忆挖掘器(Miner)缺少增量模式
**问题**：Miner 的三种挖掘模式（Project/Conversations/General）每次全量扫描。
**影响**：大型项目（如 cowd 自身 14080 节点）下初始挖掘耗时。

## 4. 记忆框架最大化价值方案

1. **引入抽象存储层**：将 JSONL 替换为支持事务的存储（SQLite/RocksDB），保持 JSONL 为导出格式
2. **向量存储解耦**：添加 EmbeddingStore trait，支持 LadybugDB + 外部后端
3. **动态压缩策略**：根据模型上下文窗口大小自动选择压缩级别
4. **增量挖掘**：Miner 支持基于文件修改时间戳的增量更新
5. **记忆分片**：大项目按社区(Community)分片存储和检索
