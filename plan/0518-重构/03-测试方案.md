| 测试 | 说明 | 期待事件序列 |
|------|------|------------|
| `full_turn_text_only` | 纯文本回复 | TurnStarted → TextDelta* → TurnComplete |

## 4. E2E 测试

### 场景 1：完整对话流程

```
启动 TUI
  → 输入 "list files in src/"     → 流式渲染回复
  → 工具卡片显示 glob_search 执行  → 进度更新
  → 工具完成                       → ✅ 状态
  → 最终回复渲染完成               → TurnComplete
  → 检查 token/cost 状态栏          → 正确
  → 输入第二个问题                  → 正常执行
  → 退出 TUI                       → 会话文件存在
  → 重新启动并恢复                  → 历史消息可见
```

### 场景 2：错误恢复

```
启动 TUI
  → 输入触发 API 错误的问题        → 错误消息渲染（非 stdout）
  → TUI 不崩溃                     → 状态栏正常
  → 再次输入                       → 正常执行
  → 检查会话文件                   → 无损坏
```

## 5. 性能基准测试

| 指标 | 目标 | 测试方法 |
|------|------|---------|
| 事件处理延迟 | < 1ms/event | 批量发送 1000 events，测量处理时间 |
| 渲染帧率 | > 30fps (流式) | 1000 字符流式输入，测量 draw 间隔 |
| 内存占用 | < 200MB (1000 消息) | 模拟 1000 条消息历史，检查 RSS |
| 启动时间 | < 500ms | 测量 TUI 从启动到可交互的时间 |
| 取消延迟 | < 500ms | 工具执行期间 Ctrl+C，测量到 UI 更新 |

## 7. CI 集成

```yaml
# .github/workflows/tui-test.yml
tui-test:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: dtolnay/rust-toolchain@stable

    # 单元测试
    - run: cargo test --lib -p cowd-cli -- tui

    # 集成测试（mock API）
    - run: cargo test -p cowd-cli --test tui_integration

    # 编译检查（无 warning）
    - run: RUSTFLAGS="-D warnings" cargo build -p cowd-cli

    # Clippy
    - run: cargo clippy -p cowd-cli -- -D clippy::all
```
