## 2. 已识别的缺陷（按严重程度排序）

### P0-致命：stdout 与 ratatui 渲染冲突

**问题**：`run_turn()` 在 TUI 模式下通过 8 个不同点向 stdout 直接写入，绕过 ratatui 的缓冲管理。

| 位置 | 写入方式 | 内容 |
|------|---------|------|
| main.rs:3266 | `spinner.tick()` → crossterm ANSI | "🦀 Thinking..." |
| main.rs:3277 | `spinner.finish()` → crossterm ANSI | "✔ ✨ Done\n" |
| main.rs:3282 | `println!()` | 空行 |
| main.rs:3284 | `println!()` | auto-compaction 通知 |
| main.rs:3294 | `spinner.fail()` → crossterm ANSI | "✘ ❌ Request failed\n" |
| main.rs:6541 | `write!(out, markdown)` | 流式 Markdown 渲染 |
| main.rs:6555 | `render_thinking_block_summary` | "▶ Thinking hidden\n" |
| main.rs:6574 | `writeln!(out, tool_call)` | 工具调用显示 |

**根因**：`prepare_turn_runtime(true)` 硬编码 `emit_output=true`。`run_turn` 为纯文本 REPL 设计，TUI 添加后未重构。

**影响**：ratatui 0.29 使用双缓冲 diff 渲染。外部 stdout 写入不被 ratatui 追踪，diff 引擎无法清理被污染区域，导致终端画面重叠混乱。

### P0-致命：Thinking 内容三处丢失

**已修复**（前置 PR），见 main.rs 修改：
- `consume_stream` line 6553: `ThinkingDelta { .. }` → 推送 events
- `push_output_block` line 7481: `Thinking { thinking, .. }` → 推送 events
- `convert_messages` line 7702: `Thinking { .. }` → `InputContentBlock::Thinking`

### P0-致命：Session clone 共享持久化路径

**问题**：`Session` 的 `#[derive(Clone)]` 完整克隆了 `persistence: Option<SessionPersistence>`，其中包含 `path: PathBuf`。clone 出来的 session 与原始 session 指向同一文件。

**执行流程**：
```
1. prepare_turn_runtime → session.clone() → clone 有同一 persistence path
2. conversation.rs:run_turn:
   a. push_user_text → append_persisted_message → 写入真实文件 ✓
   b. API 调用 #1: 返回 tool_use → push_message → 写入真实文件 ✓
   c. 工具执行 → push_message(tool_result) → 写入真实文件 ✓
   d. API 调用 #2: 400 错误 → Err
3. run_turn 返回 Err → replace_runtime 不调用 → clone 被丢弃
4. 文件中有不完整消息序列（user + tool_use + tool_result，无最终回复）
```

**影响**：会话文件被部分持久化，下次恢复时可能有不完整的消息对。

### P1-严重：ConversationRuntime 同步阻塞

**问题**：整个 `ConversationRuntime::run_turn` 是同步阻塞的，不支持 streaming 回调。

**影响**：
- TUI 只能看到 all-or-nothing 的结果
- 无法实现实时流式渲染
- 工具执行期间 UI 完全冻结
- 无法支持取消操作（Ctrl+C 中断响应慢）

### P1-严重：TUI 不展示历史消息

**问题**：`run_tui_repl` 中 `app.messages` 只包含当前 TUI session 的消息，不加载 `cli.runtime.session().messages` 历史。

**影响**：恢复会话后，对话历史不可见。用户看到空白聊天窗口。

### P2-中等：TUI 渲染无 Thinking 内容展示

**问题**：TUI 不渲染 Thinking blocks（思考链）。Server 路径通过 SSE `event: thinking` 传递。

**影响**：使用 DeepSeek/Claude thinking mode 时，用户看不到模型的思考过程。

### P2-中等：工具进度不可见

**问题**：TUI 无工具进度回调。Server 路径通过 `SseToolCallback` 发送 `tool_start/progress/complete` 事件。

**影响**：长时间工具执行期间 UI 冻结，用户无法判断进度。

## 3. Server 路径（参照实现）

Server 路径已具备 TUI 需要的所有能力：

| 能力 | Server 实现 | TUI 状态 |
|------|------------|---------|
| 流式文本渲染 | SSE `data:` chunks | ❌ stdout 污染 |
| Thinking 事件 | SSE `event: thinking` | ❌ 不展示 |
| 工具进度 | SSE `tool_start/progress/complete` | ❌ 不展示 |
| Token 统计 | SSE `event: context_usage` | ✅ 状态栏 |
| Cost 统计 | usage_tracker | ✅ 状态栏 |
| Compaction | 运行时自动 | ✅ 自动 |
| 会话恢复 | session store | ✅ 基础支持 |

## 4. 目标：TUI = Server 能力超集

TUI 不应是 Server 的"降级版"，而应承载 Server 的全部能力，加上交互式优势：

```
Server SSE events          →    TUI ratatui rendering
─────────────────────────────────────────────────────────
text delta                 →    流式字符追加到消息面板
thinking delta             →    折叠/展开思考链面板
tool_start                 →    工具卡片创建（⏳ 状态）
tool_progress              →    工具卡片进度更新
tool_complete              →    工具卡片完成（✅/❌ 状态）
context_usage              →    状态栏 token 进度条
error                      →    错误卡片/提示
```
