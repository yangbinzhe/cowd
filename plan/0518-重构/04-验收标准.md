# 验收标准

> 版本：v1.0 | 日期：2026-05-18

## 1. 核心验收（必须全部通过）

### AC-1: 零 stdout 泄漏

```
验证方法：
  $ cowd 2>/tmp/tui.log
  # 执行 3 个完整的 turn（文本 + 工具调用 + 错误恢复）
  # 退出后检查 /tmp/tui.log

期望：/tmp/tui.log 为空（或仅含 session 元数据 JSONL）
禁止：任何 write!(stdout)、println!、eprintln! 出现在 TUI 模式
例外：启动前的 bootstrap 提示（"按 Enter 键启动..."）允许
```

### AC-2: 流式渲染

```
验证方法：输入一个会产生长文本回复的问题

期望：
  - 文本逐字符/逐行追加到聊天面板
  - 追加过程流畅，无肉眼可见闪烁
  - 最后一个字符显示后 <200ms 内状态栏更新 token/cost
  - 自动滚动跟随最新内容
```

### AC-3: 事件驱动渲染

```
验证方法：输入一个会触发工具调用的问题（如 "ls src/"）

期望：
  - 工具开始前的"Thinking"文本先流式显示
  - ToolStart: 工具卡片出现，带 ⏳ 图标
  - ToolProgress: 工具卡片状态更新（进度文本）
  - ToolComplete: 工具卡片变为 ✅/❌，显示输出/退出码
  - 工具后的文本继续流式显示
  - 整个过程中 TUI 不冻结，可切换面板
```

### AC-4: Thinking 面板

```
验证方法：使用 DeepSeek（或其他 thinking model）

期望：
  - thinking 内容不显示在聊天面板（不在正常回复中）
  - Thinking 面板默认以折叠状态出现（底部或侧边）
  - 折叠时显示 "[Thinking] 128 chars hidden"
  - 点击/快捷键展开后显示完整思考过程
  - 思考过程结束后面板自动折叠（或保持展开）
```

### AC-5: 会话安全

```
验证方法：
  1. 正常完成 2 个 turn，退出
  2. 检查会话文件：cowd --resume latest /status
  3. 重新启动 TUI，确认历史消息可见
  4. 第 3 个 turn 触发 API 错误（断开网络/错误 key）
  5. 退出，再次检查会话文件

期望：
  - 步骤 2 的会话文件包含完整的前 2 个 turn
  - 步骤 5 的会话文件与步骤 2 完全相同（错误 turn 未修改文件）
  - 重新启动后前 2 个 turn 的历史消息仍可见
```

### AC-6: 取消支持

```
验证方法：
  1. 输入一个会触发长时间工具执行的问题
  2. 工具执行期间按 Ctrl+C

期望：
  - TUI <500ms 内显示 "Cancelled" 状态
  - 工具卡片更新为 ❌ (cancelled)
  - TUI 进入就绪状态，可以继续输入
  - 部分完成的 turn 不写入会话文件
```

## 2. 性能验收

| 指标 | 目标 | 测量方法 |
|------|------|---------|
| P1 | 流式渲染帧率 ≥ 30fps | `app.fps_counter` 输出 |
| P2 | 事件处理延迟 < 1ms | `Instant` 计时批量事件 |
| P3 | 1000 条消息内存 < 200MB | `ps -o rss` 或 `memory_stats` |
| P4 | TUI 启动 < 500ms | `time cowd` 到可交互 |
| P5 | 空闲 CPU < 10% | `top -p $(pgrep cowd)` |
| P6 | 取消延迟 < 500ms | Ctrl+C 到 UI 更新 |
